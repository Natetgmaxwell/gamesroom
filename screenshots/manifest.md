# App Store screenshots — V0.97+ v2

App Store Connect requires screenshots at every device size the app
supports. Without them the submission is rejected.

This directory holds the V0.97+ v2 screenshot set, generated by
`scripts/make-screenshots.py` from twelve source captures of the
main-branch Debug build on the iPhone 17 Pro Max and iPad Pro 13"
M5 (iOS 27 SDK, Xcode 27). v2 fixes three blockers from v1:

1. **iPad two-pane** — the v1 iPad captures shipped a stretched
   `NavigationSplitView` (rooms list sidebar + detail pane). v2
   uses a new `-screenshots-ipad-column` launch arg that routes
   the iPad to the iPhone stack view with the iPhone-shaped column
   wrap, producing the centered-column-with-black-margins layout
   App Store Connect requires for Universal iPad apps.
2. **Ceremonial card host view** — the v1 ceremonial card capture
   showed the host's V0.84 C2 Tonight's Star picker (Best play /
   Good sport / Held the room / Showed up / Custom pills + member
   picker + Save the call CTA) instead of the member's read-only
   view. v2 adds `-screenshots-as-member` which flips the seeded
   BriefingSlot target room to `userRole = .member` for that one
   capture, so `isHost` resolves false and the picker is hidden.
3. **Caption strip on upload set** — v1 only produced a captioned
   working artifact. App Store Connect rejects baked-in overlays
   on screenshots, so the caption can't go on the upload set.
   v2 emits TWO parallel sets: the captioned working artifact
   (orchestrator + reviewer use) AND a clean caption-stripped
   upload set ready for ASC drag-and-drop.

## Pipeline

```
raw simulator captures (12 PNGs)
  ↓ scripts/make-screenshots.py
  ├── screenshots/<size>/<NN>-<surface>.png         captioned (working)
  └── screenshots/upload/<size>/<NN>-<surface>.png  clean (upload)
```

For each of the four target sizes (iPhone 6.9", 6.5", 5.5",
iPad 13"), we emit two PNGs per surface (captioned + clean), so
the output is 6 surfaces × 4 sizes × 2 sets = 48 PNGs total. The
raw input layer holds the 12 unmodified simulator captures (6
surfaces × 2 devices) so a one-off regeneration can read from disk
without rerunning the simulator loop.

## How the source captures were taken

```bash
# Build (Debug; CODE_SIGNING_ALLOWED=NO so simulator builds skip the
# codesign gate per failure-mode #8 in ios-build-verification-outside-xcode)
xcodebuild -project GamesRoom.xcodeproj -scheme GamesRoom \
  -destination "platform=iOS Simulator,name=iPhone 17 Pro Max" \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
xcodebuild -project GamesRoom.xcodeproj -scheme GamesRoom \
  -destination "platform=iOS Simulator,id=<iPad Pro 13\" M5 UDID>" \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO

# Boot + install
xcrun simctl boot "iPhone 17 Pro Max"
xcrun simctl install booted "/path/to/GamesRoom.app"

# Cold launch with the screenshot bypass (see "Screenshot mode" below).
# Sleep 10s after launch on iPad — the bypass-auth task is async and
# races with the screenshot capture on iPad if the sleep is shorter.
xcrun simctl launch booted com.gamesroom.app \
  -screenshots-bypass-auth \
  -screenshots-state=<state> \
  -screenshots-screen=<screen> \
  -screenshots-tab=<rooms|settings> \
  [-screenshots-as-member] \
  [-screenshots-ipad-column]
sleep 10
xcrun simctl io booted screenshot /tmp/gr-shot-<surface>.png
```

The six-state loop is captured by the loop in
`/tmp/gr-v2-capture.sh` on macstudio-tailnet (kept out of tree
because it points at the local DerivedData path):

| State     | Screen    | Tab       | Surface captured       | Extras                              |
|-----------|-----------|-----------|------------------------|-------------------------------------|
| empty     | empty     | rooms     | 01-create-room         | (none)                              |
| briefing  | briefing  | rooms     | 02-briefing-slot       | (none)                              |
| witness   | witness   | rooms     | 03-witness-slot        | (none)                              |
| settled   | settled   | rooms     | 04-ceremonial-card     | `-screenshots-as-member`            |
| awards    | awards    | rooms     | 05-awards-card         | (none)                              |
| witness   | witness   | settings  | 06-settings-sheet      | (none)                              |

On iPad, every launch above also passes `-screenshots-ipad-column`
to render the iPhone-column-centered layout.

## Screenshot mode (V0.97+ launch arguments)

V0.97+ extends the V0.92 launch arguments into a coordinated set so
the screenshot pipeline can drive each V0State-machine branch
without touching real data. Production (Release) builds never see
these branches — every arg reads under `#if DEBUG` or compile-gates
on the screenshot bypass only.

| Argument                              | Effect |
|---------------------------------------|--------|
| `-screenshots-bypass-auth`            | V0.92 — swap `LiveRoomStore` for `InMemoryRoomStore.shared` and inject a stub `currentUser` so the in-app surfaces render without going through Apple Sign-In. |
| `-screenshots-state=<key>`            | V0.97+ — Drive a stable demo seed for each surface. See "State keys" below. |
| `-screenshots-tab=rooms\|settings`     | V0.92 — Set the initial `TabView` selection on launch. |
| `-screenshots-screen=<key>`           | V0.92 + V0.97+ — Push the appropriate room onto the iPhone `NavigationStack` (and select the first row on the iPad sidebar). See "Screen keys" below. |
| `-screenshots-as-member`              | **V0.97+ v2** — Flip the seeded BriefingSlot target room's `userRole` to `.member` for this capture so `isHost` resolves false and the V0.84 C2 Tonight's Star host picker is hidden. Use for the ceremonial-card capture; otherwise the picker leaks into the screenshot. |
| `-screenshots-ipad-column`            | **V0.97+ v2** — Force the iPad to render the iPhone stack view (not the production `NavigationSplitView`) and wrap the content in the iPhone-shaped column so the capture shows the centered column with black iPad margin that App Store Connect's Universal iPad spec requires. |

All six live under `#if DEBUG` in `GamesRoom/`, in
`AuthService.swift`, `RoomPage.swift`, `InMemoryRoomStore.swift`,
`GamesRoomApp.swift`, and `ContentView.swift`. Production binaries
never see these branches.

### State keys (`-screenshots-state=<key>`)

| Key        | Seed                                                                                       | Resolves to |
|------------|--------------------------------------------------------------------------------------------|-------------|
| (default)  | V0.92 default — `playedAt = +2d`, `startedAt = -30min`                                     | (depends on `_screen`) |
| `briefing` | `playedAt = +2d`, `startedAt = nil`, `settledAt = nil`                                     | `.upcoming` (BriefingSlot) |
| `witness`  | `playedAt = 30 min ago`, `startedAt = 30 min ago`, `settledAt = nil`                       | `.tonightEvent` (WitnessSlot) |
| `settled`  | `playedAt = 3h ago`, `startedAt = 3h ago`, `settledAt = 30 min ago` + chapter line seed    | `.justSettled` (CeremonialCard) |
| `awards`   | Felt Faction reordered to `[0]` + leaderboard mirror; uses seed awards from `init`         | `.seasonClose` (AwardsCard on Felt Faction's ended season) |
| `empty`    | Empty rooms list                                                                            | RoomPage empty state (Create-room hero) |

### Screen keys (`-screenshots-screen=<key>`)

| Key                | Effect                                                                    |
|--------------------|---------------------------------------------------------------------------|
| `briefing`         | Push the first seeded room (the briefing-slot target)                     |
| `witness`          | Push the first seeded room (the witness-slot target)                      |
| `settled`          | Push the first seeded room (the ceremonial-card target)                   |
| `awards`           | Push the first seeded room (Felt Faction after reordering)                 |
| `empty`            | No push — leave the rooms list (rooms list is empty for this state)       |
| `room-detail`      | V0.92 alias for compatibility — push the first seeded room                 |
| `casino`           | V0.92 alias                                                                |
| `pack-detail`      | V0.92 alias                                                                |

## Tonight's Star leak diagnosis (item 4 — verify)

**Verdict: NO LEAK.** The Tonight's Star host picker (Best play /
Good sport / Held the room / Showed up / Custom pills + member
picker + Save the call CTA) is gated on a chain of three checks in
`GamesRoom/Views/RoomDetailView.swift`:

1. **Picker render gate** (line 2501):
   `if isHost, let onTonightStarPick, !hostPickMembers.isEmpty`
2. **Callback wiring** (line 914-918, `RoomDetailView.body`):
   `onTonightStarPick: isHost ? { ... } : nil`
3. **`isHost` source** (line 125-128):
   `room.userRole == .host || room.createdBy == uid`

All three must pass for the picker to render. A signed-in member
who is not the room's host hits the `nil` callback at (2), which
fails (1) and the picker is hidden. The read-only Tonight's Star
section at line 2469-2471 (the small star + "Tonight's Star" +
winner + category line) is intentionally shown to everyone — it's
the public read of the host's pick, not a control surface.

**The v1 screenshot bug was screenshot-side, not code-side.** The
bypass seeded `carwoola` with `userRole: .host` AND injected a
stub `currentUser`, so `isHost` resolved true and the picker
rendered on the `.justSettled` capture. The
`-screenshots-as-member` arg flips the seeded room to
`userRole: .member` for that one capture, so `isHost` resolves
false and the picker is hidden.

Production code paths are untouched. No privacy fix needed.

## Regenerating

```bash
# 1. Capture the 12 raw shots (6 surfaces × 2 devices) on
#    macstudio-tailnet into screenshots/raw/{iphone,ipad}/. See
#    "/tmp/gr-v2-capture.sh" for the loop.

# 2. Run the script. Reads from the default raw/ subfolder; pass
#    IPHONE_RAW / IPAD_RAW env vars for one-off regeneration.
python3 scripts/make-screenshots.py
```

The script emits both sets in one pass:

- `screenshots/<size>/<NN>-<surface>.png` — captioned working
  artifact (orchestrator + reviewer use)
- `screenshots/upload/<size>/<NN>-<surface>.png` — caption-free
  upload set, ready for App Store Connect drag-and-drop

Re-capture sources first if the UI has shifted; the `raw/iphone/`
and `raw/ipad/` directories hold the inputs (six PNGs each).
