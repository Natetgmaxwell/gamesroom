- **Store layer**: new `RoomStore.releaseSeat(eventId:state:)` on the protocol, `LiveRoomStore` (calls the `release_seat(p_event_id, p_state)` RPC from migration 113) and `InMemoryRoomStore` (mirrors it: RSVP moves, a held deposit resolves to `.returned`, the member leaves the arrival list). - **RoomService.releaseSeat(eventId:state:)** routes decline (`.declined`) and release (`.unclaimed`) through `release_seat` when the event's room runs the escrow; a room the cache cannot resolve is treated as an escrow room (a stranded deposit is worse than one extra RPC); a room with deposits off keeps the plain `upsert_event_rsvp` write, which is identical there because there is no deposit to return. `RoomDetailView.declineSeat` / `releaseSeat` now call this instead of `upsertEventRSVP`.
- **`RoomService+EventChange.swift` (new)**: `eventDidChange(eventId: UUID) async` cancels the event's briefing trio, force-reloads the active event, and re-schedules the trio when the night still exists. Called after every claim / release / decline in this lane (edit + cancel come in step 4). The re-schedule is deliberate: `cancelBriefingTrio` drops the pending nudges for EVERY member, so a cancel on its own would silence the night for everyone. The reschedule reuses the exact block that used to live inside `upsertEventRSVP` (now `RoomService.rescheduleBriefingTrio(eventId:callerState:callerMemberId:)`, split out so the escrow paths push the same cadence). Notification semantics are unchanged - lane S2 owns them.
- **Escrow claim path fixed too**: `RoomService.claimSeat` used to skip the cache patch and the seat-grid reload in escrow rooms, so the server said "claimed" while the page still showed an open chair. It now patches `rsvpByEvent` and calls the new `refreshSeatCaches(eventId:)` (the reload block lifted out of `upsertEventRSVP`).
- **Release toast**: bottom overlay on the room page, `Seat released.` with a plain-text `Undo`, five seconds (`.task(id:)` + `Task.sleep(for: .seconds(5))`). Undo re-claims through the normal claim path, so a night that filled up in the meantime says so.
- **Full night**: `BriefingSlot` replaces the Claim seat button with the grey caption `All {n} seats are taken.` when `claimed >= maxSeats` and this member does not hold a chair (count = max of the briefing summary's `seatsClaimed` and the seat-grid rows). A server `night_full` (P0001, migration 113) rolls the optimistic claim back, is remembered per event (`nightFullEventIds`), re-reads the seat counts and shows the same line instead of the raw error dialog (`RoomService.isNightFullError(_:)`, `nonisolated static`).
- **`InMemoryRoomStore.claimSeatWithDeposit`** now skips the deposit insert only while a deposit is still `held` (migration 113's rule), so a released seat re-takes the deposit on the re-claim. The old mirror short-circuited on any row and left a claimed seat with no deposit behind it.
