### One thing the acceptance ledger does not say out loud

A1's premise is "confirm the live roster RPC returns `invited_by` to non-host members". It does not,
and it does not check whether the caller is a member of the room at all. TARS's probe found the live
`get_room_members` is `SECURITY DEFINER` with `search_path = ''`, `EXECUTE` granted to `PUBLIC`
(anon included), and no caller guard: any unauthenticated caller holding a room uuid could read the
whole roster, including chip balances, season scores and notification preferences. V0.107 has to widen
that same payload with the anchor, so migration 103 closes it in the same breath:

- the `where` clause gains `and exists (select 1 from public.room_memberships c ... membership_status
  = 'active')` on `public.current_user_id()` (`103_brought_by.sql:98`), so a non-member reads zero rows;
- `revoke all ... from public, anon` + `grant execute ... to authenticated` (`103_brought_by.sql:109`);
- both new functions get the same treatment, and the write path re-checks with
  `public.is_room_host` (migration 095), raising `not_authorized` (42501) — never `rooms.created_by`.

This is a breaking permission change for any anonymous reader of that RPC, which is worth a line in
the release notes when the migration is applied.

## Not done, and why

1. **A3, A5, A7, A8 have unit or by-construction cover but no sweep state or negative assertion.**
   Each is one seeded state plus one assertion away, and all four were left out to keep T8 to the
   gate, the range check and the ledger. A5 is the one I would add first: it is the check that
   guarantees D2's silent-kick rule, and today it rests on two filters neither test exercises.
2. **The `currently-into-<name>` identifier on the briefing caption is dead.** T4 added
   `brought-by-<name>` below the existing `currently-into-<name>`; SwiftUI keeps only the last
   `accessibilityIdentifier` on a view, so the old id no longer resolves. The only identifier any
   test still uses is the separate `claimed-currently-into-field` (the Claim seat input), which is
   untouched. Left in place so T4's reviewed diff stays as gated; deleting the line is a one-line
   cleanup with a gate re-run.
3. **The Currently Into line gained an `into ` prefix it did not have.** `QuestionBoxService
   .currentlyIntoLine` returned the stored text raw ("Rewatching The Sopranos"); `BroughtBy.intoPart`
   prefixes `into ` unless the member already typed it, so the line now reads "into Rewatching The
   Sopranos". That is the playbook rule and matches spec §2's `into bouldering`, and nothing in the
   repo asserted the old bare wording.
