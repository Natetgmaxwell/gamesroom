### Notes — T1 (migration 105)

- Tracked at lowercase `supabase/migrations/105_anchor_push.sql` (case-insensitive FS would have recorded `Supabase/`; S5a's review fixed 103 to lowercase, so the index path was set explicitly). The file on disk is the same directory.
- `event_rsvps.member_id` is a **user id**, not a membership id — confirmed from the 033 RLS policies (`member_id = auth.uid()`).
- Fail-closed ordering is deliberate: the pg_net extension check and the vault secret read happen **before** the `anchor_nudges` insert, so a send that never happened does not consume the one allowed nudge. When the secret is finally set, the next claim still sends.
- The trigger's release branch is guarded by `tg_op = 'UPDATE'`. `OLD` is unassigned on INSERT and the 033 default state is `unclaimed`, so an `unclaimed` row arriving fresh would otherwise raise.
- Self-invite (`invited_by = user_id`) is rejected in the inviter lookup.
- Night count = `events.settled_at is not null` in the room with a claimed RSVP held by the newcomer (033 added `settled_at`).
- `set_anchor_push_enabled` raises `not_a_member` (42501) when the caller has no active membership; no host check, because the predicate is the guard.
- No gate was run for T1 — the playbook names gates only for T2 (`deno test`) and T3 (`.maestro/gate.sh`). Nothing was applied, deployed, or set against Supabase.

### Notes — T2 (edge function)

Git on this case-insensitive volume resolved the directory as `Supabase/` on a plain `git add`, so the index entries were set with `git update-index --cacheinfo` after hashing the blobs (`git ls-tree -r HEAD` now reads `supabase/functions/anchor-nudge-push/...`). Note the pre-existing `Supabase/functions/question-turn-push/` is still capital-cased in the tree; renaming it is outside this slice.
- `apns.ts` is **imported, not copied or edited** (`../question-turn-push/apns.ts`). So is `secretsMatch` — the constant-time secret compare is re-exported from `../question-turn-push/handler.ts` rather than duplicated, so the two gates cannot drift. `SendResult` / `TokenRow` are imported as types. Only a private 5-line `json()` helper is local.
- Two inherited behaviours worth a reviewer's eye, both flagged in `index.ts`: (1) `apns.ts` derives `apns-collapse-id` from `payload.turn_id`, and APNs rejects an empty one, so `index.ts` wraps the sender and supplies `anchor-<event_id>` under that name — header only, nothing reads it. (2) `apns.ts` hard-codes `apns-expiration` to +10 min (a question is stale after that), so an anchor nudge inherits the same window; not editable without touching shared APNs code, so a device unreachable for ten minutes loses the nudge instead of getting it hours later.
- Gate order is `POST` → 405, secret gate → 401, uuid shape → 400, `ANCHOR_PUSH_ENABLED` → 200 `disabled`, then work. Nothing touches the DB before the disabled check, so the flag alone stops the sender.
- Only one rule is re-checked here: **the event has not started** (A12). SQL already decided membership, both switches, "inviter not seated" and "first three nights"; the ledger row is the proof. Re-implementing them would be a second copy of the rules to keep in step. The started-event rule is the one whose truth moves with the wall clock while pg_net is in flight.
- `push_status` vocabulary: `sent` (any token accepted), `failed` (every token errored), `no_device` (inviter has no active iOS token), `skipped_started`, `already_sent`. `already_sent` also covers a duplicate delivery of the same post — the primary key in migration 105 already stops a second queue, this stops a redelivery.
- Display name comes from `public.users.display_name` — the column `get_room_members` returns (migration 059), i.e. the name the room already shows. There is no room timezone column anywhere in `supabase/migrations` (grepped `time_zone` / `timezone`, no hits), so `ROOM_TIME_ZONE = "Australia/Brisbane"` is hard-coded with the reasoning in the file.
- Copy is rendered with `Intl.DateTimeFormat` in the room's zone, not by adding milliseconds: `calendarDaysBetween` differences the two **calendar dates**, so a 00:30 Saturday Brisbane event reads as Saturday even when it is still Friday in UTC, and the six-day boundary is the room's midnight rather than UTC's.
- Tests (15, `deno test supabase/functions/anchor-nudge-push/`): missing/wrong/unset secret 401, disabled flag, copy within and past six days, 6-vs-7-day boundary, tonight reads as today, blank name, Brisbane-vs-UTC weekday, inviter is the only recipient (a body-supplied recipient is ignored and the name read is the newcomer's), started event skipped, already-sent skipped, no device, all-APNs-failed → `failed`, 410 deactivates the token and the ledger row is marked, payload carries `room_id` + `event_id`, bad input / unknown ledger row / unknown event / 405.
