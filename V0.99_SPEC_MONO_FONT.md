## Integration notes (build lane)

- Bundle the .ttf(s), register in Info.plist (`UIAppFonts`), expose as a
  `Theme.Font.mono` token in the app's design tokens — no raw font-name strings at
  call sites.
- Fallback chain: `Maple Mono → SF Mono → Menlo → system monospace`.
- Weight: use the variable axis; default 400, semibold 600 for hero numerals
  (live scores/timers). Do not fake bold with SwiftUI `.bold()` on a custom font —
  set the axis/weight explicitly.
- Dynamic Type: scale the mono role manually off the current `dynamicTypeSize`
  (monospace + `.relativeTo` text style via `Font.custom(_:size:relativeTo:)` —
  anchor to `.body`). Verify at AX sizes XL–XXXL that timer/score rows don't clip.
- Emoji/symbol fallback is system — Maple covers Latin + common symbols only; do
  not expect ✓/± coverage checks to fail builds (visual QA only).

## Slice (small, shippable alone, ~1–2 h)

1. Add font files + licence + Info.plist registration + `Theme.Font.mono` token.
2. Apply the token to: room join/pack code displays, score numerals, timers,
   ledger table numerals. Nothing else.
3. DoD: build green on BOTH toolchains (Xcode.app 26.6 + Xcode-beta 27, full
   paths); codes legible and unambiguous at default size; no body copy in Maple.

## Out of scope
