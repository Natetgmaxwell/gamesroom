# V0.98_SPEC — Members & host tools (kick, visible host controls, team-input removal)

Governing principle: **the host is the customer** (V0.53 §6) and **the ledger is the
durable social** (V0.53 §5). Kicking a member must give the host control without ever
vaporising a person's nights. The kick is **silent** — quiet by default (V0.53 §4).

## Hard invariants

1. **No delete path.** `room_memberships` rows are never deleted by kick. Only the
   member's own `leave_room` deletes (unchanged).
2. **The kicked member sees nothing.** Every client path that could surface the room
   to them filters `membership_status = 'active'` (see touchpoint list). If any path
   leaks, the member sees a ghost room — that is a bug, not a edge case.
3. **Status lives server-side only.** The iOS `Member` model does NOT gain a status
   field on any rendered surface. Roster queries simply never return kicked rows.
4. **Every state change goes through a SECURITY DEFINER RPC** with the guard checks
   inside the function — never through RLS-only enforcement (client uses RPCs; RLS
   is defence in depth).
5. Voice/face never narrate a kick. No mascot copy mentions membership changes.

## DB — migration `093_member_kick.sql`

### 1. Column

```sql
alter table public.room_memberships
  add column if not exists membership_status text not null default 'active'
    check (membership_status in ('active', 'kicked'));
comment on column public.room_memberships.membership_status is
  'V0.98 — Option A kick. kicked = row preserved (ledger/season/history intact), excluded from all roster + visibility paths. Never surfaced to the member (D2).';
```

All existing rows default 'active'; existing behaviour unchanged.

### 2. `remove_room_member(p_room_id, p_target_user_id)` RPC

SECURITY DEFINER, `set search_path = ''`, same shape as `transfer_host_role` (091):

- caller must be a host **role** in this room (membership check, not `created_by`) → else `not_authorized`
- target must be a member of the room → else `not_found`
- target must not be a host (any host) → `is_host` error ("demote first" — one tool per row, prevents host-lockout accidents)
- target must not be the caller → `is_self` error
- **live-event guard:** if the target has a `seat_deposits` row with status `held` on an event where `played_at <= now()` and the event is not settled → `active_deposit` error (settle the night first; escrow money must not evaporate)
- refund path: `held` deposits on **future** events (`played_at > now()`) are set to `refunded`, `settled_at = now()` (D5)
- future-event RSVPs by the target: left in place — they become inert because every roster/seat surface filters on active membership (verify in slice 3; add explicit filters where needed)
- sets `membership_status = 'kicked'` on the target row
- returns the **active-only** roster (same shape as `get_room_members`) so iOS rebuilds the cache from one round-trip, mirroring 091's pattern
- idempotent: kicking an already-kicked member is a no-op returning the roster

### 3. `redeem_join_code` reactivation (D6)

Rewrite (018 lineage). The existing-membership idempotency branch changes:

- row exists and `membership_status = 'active'` → current behaviour (return room, no mutation)
- row exists and `membership_status = 'kicked'` → reactivate: `membership_status = 'active'`,
  `points_balance = room.join_starting_bonus`. season_score, team, history untouched.
  The redeemed code is consumed as normal (single-use unchanged — the host must
  generate a fresh code per rejoin, which is the implicit approval)

### 4. `leave_room` guard fix (D7)

Replace the `created_by` check with: caller's membership role = 'host' → allowed only
if ≥1 OTHER active host remains (else `last_host` error, matching 091). Members leave
freely. Returns boolean as before.

### 5. Visibility touchpoints — kicked rows must vanish (invariant 2)

Audit and patch each:

| Touchpoint | File | Change |
|---|---|---|
| `get_my_rooms` | 006 lineage | join gains `and m.membership_status = 'active'` — kicked room leaves their room list (THE D2 surface) |
| `get_room_members` (+ 066 variant) | 059 / 066 | filter active |
| `get_room_detail` RPCs | 008 lineage | verify membership-derived fields exclude kicked rows |
| RLS `user sees own memberships` | 004 | add `(membership_status = 'active')` to the using clause |
| RLS `member sees room` on rooms | 004 | add status filter inside the exists() |
| RLS `host sees room members` | 004 | add status filter (host roster is active-only) |
| seat/RSVP surfaces | 043/090 lineage | verify kicked member's stale future RSVPs can't be claimed/counted; add active-membership filters where the query is membership-driven |

Every RPC in this migration is `create or replace` (idempotent, re-runnable), matching
house style. Header comment carries the apply-via-psql stanza from 018.

## iOS

### Slice 1 — team input removal (D4, ~30 min, shippable alone)

- `RoomSettingsSheet.swift`: delete the `TextField("Team", ...)`, `teamBinding(for:)`,
  `commitTeam(_:)`, and the "Team labels group members on the leaderboard…" caption.
  The two member/host row layouts keep their structure minus the field.
- The "To leave the room, ask another host to demote you." footer note stays (still
  true post-D7 for the last-host case).
- No model/store/service changes — `setMemberTeam` stays wired and unused, like the
  DB column (D4).
- DoD: build green on BOTH toolchains (Xcode.app 26.6 + Xcode-beta 27, full paths);
  Members sheet renders on host and member views with no team field.

### Slice 2 — visible host controls on member rows (~1–2 h)

- Replace per-row context menus in `RoomSettingsMembersSheet` with a visible trailing
  **"···" menu button** (`Menu`) on rows the caller can manage — same rows that have
  context menus today. Items: "Make host" (member rows) / "Demote to member" (host
  rows, destructive role). Kick lands in the same menu in slice 3.
- Keep the existing `pendingChange` confirm-alert pattern verbatim (it already
  promotes the dialog to sheet level — the exact reason context menus were awkward).
- Self-row and member-viewer rows: no menu (unchanged).
- DoD: host sees the affordance without long-press; confirm alerts fire the right
  RPC; member viewer sees plain rows.

### Slice 3 — kick (~half a day incl. migration)

- `RoomService.kickMember(roomId:memberId:)` → `remove_room_member` RPC; roster cache
  rebuilt from the returned rows (mirror `transferHostRole`).
- Members row menu gains "Remove from room" (destructive) for member rows. Confirm
  alert copy: title "Remove \(name) from the room?"; message "Their nights stay in
  the ledger. They can rejoin later with a new invite code." Confirm button
  "Remove". The `PendingRoleChange` action enum gains `.kick`.
- `Member` model: no status field added (invariant 3). If the decoder needs it,
  `decodeIfPresent` private — never rendered.
- Live-event guard error (`active_deposit`) surfaces through the existing transferError
  alert path with the server message.
- Apply migration to the live DB BEFORE the build that calls the RPC (app must never
  ship calling a missing function — 091 ordering precedent).

## Out of scope (deliberate)

- Blacklist/ban UX — the 022 RPCs exist server-side, unused. Flipping that on is a
  future spec; rejoin-by-code is the only path for now (D6).
- Un-kick UI — a fresh invite code is the un-kick (D6).
- Mascot narration of kicks — never (invariant 5).
- Team data backfill/cleanup — the column stays, dead (D4).
