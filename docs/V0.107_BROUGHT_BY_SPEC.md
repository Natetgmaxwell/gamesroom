# V0.107: Brought By (polish slice S5)

Status: DRAFT for Nathan's sign-off, 2026-10-22. Branch base: S3 tip `4b9c81a` (S4 runs in parallel; this slice stacks on S4 at build time).

## 0. Why

North star (Nathan, 2026-10-22): Games Room is a relationship machine dressed as a gaming club. The machine works in outcomes, never in vocabulary: no "network", "connect", profiles, feeds or DMs.

Nathan's correction to TARS's first read: a newcomer never arrives cold. Every new member comes through someone who is already in the room. That anchor is the design's strength: the newcomer has someone they're happy to talk to, which lowers the cost of saying yes.

So the job is not to warm up strangers. It is to **make the anchor visible to everyone else**, so the regulars can include the newcomer through a person they already know, and the newcomer's second and third conversations come easily. A newcomer the room can place ("Sam, Alex's mate, first night") is a newcomer people talk to.

Already shipped, do not rebuild: "Who's coming" in the briefing with each person's Currently Into line (V0.106, `WhosComingList`, migration 097). The Question Box reader card's answer-first line. Tier-2 invite approval queue (V0.55).

## 1. Design rules

1. Ride existing surfaces only: the briefing's Who's coming list, the room's seat grid, the host's Pending invites list. No new screen, sheet, card or push.
2. The anchor line is context, not a label. Plain caption text, same grey as Currently Into, joined with " · ". No badges, pills or icons.
3. "First night" shows only until that member has played one night. Stale context hides itself.
4. Never single the newcomer out at the table. Nothing in this slice changes the Question Box reader or answer-first logic (the default member preference text asks not to be singled out without warning).
5. The anchor name is whatever the room already shows for that member (display name in this room). If the inviter has left or been kicked, the line drops the anchor and shows "first night" only. A kicked member's name never appears (D2 silent-kick rule).

## 2. What changes

| Surface | Today | After |
|---|---|---|
| Briefing, Who's coming | `Sam` / `into bouldering` | `Sam` / `with Alex · first night · into bouldering` |
| Seat grid, claimed seat caption (accessibility label and the named list under the grid) | `Sam` | `Sam, with Alex` |
| Host Pending invites row | `Sam    Remove` | `Sam` / `via Alex`    `Remove` |

Order inside the caption: anchor, then first night, then Currently Into. Any missing part drops out with its separator. A member with no inviter (tier 1 host, tier 3 open code) shows no anchor.

## 4. Data

No new tables or columns.

- Anchor: `room_memberships.invited_by` (V0.55, migration 068) mapped to the inviter's active membership in the same room, already decoded on `Member.invitedBy`.
- First night: the member has no settled event in this room where they held a seat (claimed RSVP). Prefer a value the client already has (leaderboard `sessionsPlayed == 0`); if that is not available on the briefing path, compute from cached RSVPs. No new RPC unless check A1 fails.
- Setting: needs one boolean on `rooms`. That is the only schema change and it is additive (`show_brought_by boolean not null default true`) plus a host-only RPC in the role-based `is_room_host` pattern. Migration written, NOT applied; orchestrator applies after sign-off.

## 6. Acceptance checks

A2. Briefing with a seeded tier-2 member on their first night shows `with <inviter> · first night · <currently into>` under their name.
A3. Same member after one settled night shows `with <inviter> · <currently into>` (first night gone).
A4. Member with no inviter shows no anchor text.
A5. Inviter kicked: the newcomer's line shows `first night` only; the kicked name appears nowhere on the page.
A6. Host Pending invites row shows `via <inviter>`.
A7. Setting off: no anchor or first-night text on any surface for that room.
A8. Seat grid accessibility label reads `<name>, with <inviter>` for an anchored member.
A9. No new cards, chips, badges, icons or colours (screenshot review against the rubric).
