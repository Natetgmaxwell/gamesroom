## 0. Design rules (the Sutherland test)

Every requirement below is checked against these. A requirement that breaks
one is cut, not negotiated.

1. **Members never see a new screen.** Both features ride the existing RSVP
   (Claim seat) card and the existing Briefing. Claim stays one tap
   (RoomDetailView `onClaim` → `claimSeat`, no confirmation sheet exists).
   The optional field appears inline on the **claimed** state of the same
   card after the tap, never as a gate before it.
2. **The default does the work.** A host who never opens settings gets a
   working feature. A member who ignores every field loses nothing.
3. **One ask per RSVP, maximum.** Never two optional fields at once.
4. **Skipping is the default.** No validation, no nudges, no reminders, no
   "complete your profile."
5. **Nothing on members' phones during play.** Questions surface only on the
   host's surface, between games (V0.53 §3.2, §4).

## 1. Question Box

### 1.1 Room settings (host only)

Room Settings gains a **Questions** section:

| Setting | Type | Default |
|---|---|---|
| Question Box | toggle | **On** |
| Show who asked | toggle | **Off** (anonymous) |
| House deck | toggle | **On** |
| Questions | list → edit screen | — |

- Turning Question Box off hides the RSVP field and stops question turns. Data is
  kept; turning it back on restores it.
- **Show who asked** off: the room never sees authorship. The host always sees
  it in the Questions list (moderation). On: the drawn card shows "asked by
  {name}".
- **Questions edit screen:** one list, member questions first then house deck.
  Tap to edit text, swipe to delete, + to add a host question, a "Drawn"
  section with swipe-to-restore. Deep/unhinged tag shown as grey secondary
  text, editable.

### 1.2 House deck

- ~40 seeded questions, each tagged `deep` or `unhinged`, roughly 50/50.
- Ships as bundled data (not network-fetched). Every new room gets a copy, so
  host edits never touch other rooms.
- Register: the **Mostly Wise** vibe (Modern Wisdom's round-table hangout
  series, e.g. #1156 with Sexton, McCusker, Glassman). Reference only; the
  name is not used. What to copy from it:
  - Every segment is a question. Chapter titles read like the deck should:
    "Why is funny and attractive so hard to find?", "Can you tell your
    partner they've gained weight?", "Who is Fred Rogers?",
    "What happened to multi-cam sitcoms?".
  - Questions that are personal, opinionated and open, not trivia. They work
    because anyone at the table can have a take.
  - Hard swings in register inside one night: relationships and status to
    pure nonsense and back. The deck alternates tags to reproduce that.
  - Rough edges allowed. A house deck can be cheeky; host editing covers
    rooms that want it cleaner.
  - **Answerable in ~10 seconds** (Nathan, 2026-10-03). Every question gives
    direction: a forced choice, one specific thing, or a named person/object.
    "Any belief you hold" fails; "one job you think is a scam" passes. No two
    questions that ask for the same kind of answer.
  Paul Conway's group-chat list (brain: `inbox/clippings/paul-conway-…`) is
  the floor for the unhinged half. Deck: `docs/V0.106_house_deck.json` (40, 20/20,
  writing t_64f1cd97 + TARS edits 2026-10-03). Bundle it as the seed deck.

### 1.3 Member contribution (RSVP)

- After Claim, the claimed-state card shows **one optional single-line field**
  inline ("You're in." + field). Claiming never waits on it.
- Placeholder shows a rotating example from the house deck ("e.g. What would
  you be famous for in 1850?"). Max 140 chars.
- Empty submit is the normal path. No validation message, no follow-up.
- A member can contribute at most one question per event. Editing their RSVP
  shows their question pre-filled.
- Field hidden when Question Box is off, or when the one-ask rule (§3) picks
  Currently Into.

### 1.4 Delivery: the rotating reader (Nathan, 2026-10-03, rev 2)

The question is read aloud by a **different member each time**. The tech
serves the group: one person looks at one screen, briefly, because it's their
turn to ask. Modelled on Chris Williamson's Mostly Wise: a concrete prompt
dropped at a pause, then the table runs with it.

**Who (in order):**
1. **The host always asks the first question** of the night.
2. Then rotation through members who have **withdrawn chips this event**
   (a withdrawal transaction exists for them on tonight's session; migration
   040 / EventTransaction). A withdrawal is the arrival signal: they're at the
   table and playing. Order = order of their first withdrawal.
3. Packs with no bank/withdrawals: fall back to claimed members who have
   been checked in / scored, else claimed members in claim order.
4. **Pass** hands the turn to the next eligible person; a pass doesn't skip
   them next round. Rotation state persisted per event.

**When:**
- **Opener:** host, at the event start time (`played_at`) once the event is live.
- **During play is allowed** (Nathan override of "never mid-game"; justified
  because only the reader's phone is involved, never the table's).
- Cadence: **fixed interval only** (Nathan, 2026-10-03): one turn every
  **N minutes** while the event is live (host setting, default 20, options
  10/20/30/off). No event-driven triggers: not on score saves, withdrawals,
  cash-outs or any other action. Interval measured from the previous turn.
- Turns stop when the event is settled.

**How it reaches the reader:**
- **Push to the reader only** (APNs, server-sent). One notification, to one
  person: title "You're asking", body = the question. Tapping opens the
  full-screen card. Never sent to anyone else; no table-wide push, ever.
- If the app is open, RealtimeEventService shows the card directly (no push).
- **Host fallback:** host surface shows "Sam's asking" with the question
  behind a tap, so a dead phone never stalls the round.

**The reader's card (designed to make the table listen):**
- Large type, one question, nothing else. Buttons: **Done**, **Pass**.
- A one-line read-out script above the question: "Question from the box:" so
  the reader has a ritual opener that cues the table.
- Optional: "Pick who answers first" helper line (name suggestion: the person
  to the reader's left). See §1.5.

**Infra required (new):** APNs auth key (.p8) + Push Notifications
entitlement + device token registration table + a `question-turn-push`
Supabase edge function (sender) + a scheduler (pg_cron or edge cron) for the
cadence. The APNs key is created by Nathan in the Apple Developer portal;
the build ships with the sender disabled until the key secret exists.

### 1.5 Getting the table to listen (product levers only)

- **Ritual opener.** "Question from the box" is the gavel. Same words every
  time, so the table learns it means look up.
- **Directed first answer.** Open questions to a group die (diffusion of
  responsibility). The reader names who answers first; the card suggests the
  person on their left.
- **Reader answers last.** Keeps the reader as host of that question, not
  performer.
- **Speaking light (torch).** While the reader's card is open, the phone's
  torch turns on at low level (`AVCaptureDevice.setTorchModeOn(level:)`,
  ~0.1, steady, never flashing). With phones face down on the table it reads
  as a glow from the asker's spot. Off on Done/Pass, auto-off after 3 min.
  Foreground-only (iOS can't drive the torch from a push), so it starts when
  the reader opens the card. Room setting "Speaking light", default on.
  Skip silently on devices without a torch (iPad) or if the torch is busy.
- **Physical token (no code).** Recommend in onboarding/house-rule copy: the
  reader holds a designated "question chip" from the chip set while asking.

## 2. Currently Into

### 2.1 Data

- Reuse existing `preferences_conversation_prompt`
  (`SocialPreference.conversationPrompt`, migration 026). UI cap 60 chars.
- Add `preferences_conversation_prompt_updated_at timestamptz` (new
  migration). Server sets it on every write.

### 2.2 Capture (RSVP only)

- Shown on the claimed-state card as one optional line
  ("Currently into…") **only when** the value is empty or
  `updated_at` is older than 30 days.
- Pre-filled with the last value when stale, so keeping it is one tap.
  Clearing it is allowed.
- No profile-screen editor in V0.106.

### 2.3 Display (Briefing only)

- In the Briefing's who's-coming list, grey secondary text under each claimed
  member's name.
- Hidden automatically when older than 30 days. Hidden when empty (no
  placeholder, no dash).
- Visible only to members of the same room (existing RLS on
  `get_room_members`; verify, don't assume).

## 3. The one-ask rule

On the claimed-state card, show exactly one optional field or none:

1. Currently Into is empty or stale → show **Currently Into**.
2. Else Question Box is on → show **question field**.
3. Else → nothing.

## 4. Data model

New table `room_questions`:

| column | type | notes |
|---|---|---|
| id | uuid pk | |
| room_id | uuid fk rooms | |
| event_id | uuid fk events, nullable | set for member questions |
| author_id | uuid fk users, nullable | null for house/host-seeded |
| source | text | `member` \| `host` \| `house` |
| text | text | ≤140 |
| tag | text | `deep` \| `unhinged` \| null |
| drawn_at | timestamptz null | |
| created_at | timestamptz | |

Room columns: `question_box_enabled bool default true`,
`question_show_author bool default false`, `question_house_deck bool default true`.

RLS: members insert their own `member` rows for rooms they belong to; only the
host reads `author_id` when `question_show_author` is false (expose via RPC,
not raw select); only the host updates/deletes. Account deletion
(migration 096) must null `author_id` or delete the member's rows — decide in
build, document in the migration.

## 5. Acceptance

1. A member who ignores both fields completes RSVP in the same taps as today.
2. Never more than one optional field on the claimed-state card.
3. New room, settings untouched → host gets the opener at start time; subsequent turns rotate through members with a withdrawal, on the 20-min interval only.
4. A question turn (push or card) reaches only the reader's device and the host fallback; never any other member's device.
5. Show-who-asked off → no member-facing surface reveals authorship
   (checked via RPC response, not just UI).
6. Currently Into older than 30 days does not render in the Briefing.
7. Host can edit, delete, add, and restore questions; changes are room-local.
8. Account deletion leaves no orphaned authored questions.
9. Build green on both Xcode gates; XCUITest covers 1, 2, 3, 6.
