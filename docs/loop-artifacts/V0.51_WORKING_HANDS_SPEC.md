# V0.51 — Chips on the table: per-member working-hand readout

## Goal
During casino play, show every member's current working hand (chips
withdrawn from their points) at a glance — not just the caller's own badge.
Host sees every member's working hand AND their bank balance plus the
to-dispense zone. Members see working hands only (no balances). The
host-only dispensing surface merges into this one section.

## Design decisions (owner: orchestrator — do not relitigate)
1. **Render gate for the section:** render during active casino play when
   at least one member has `working_hand > 0` OR there are pending
   withdrawals to dispense. Hide when empty. "Active casino play" =
   `event.packSlug == "casino" && event.playedAt <= Date() &&
   event.settledAt == nil` (covers both `.inPlay` and `.settleRound`).
2. **Balance visibility:** bank `points_balance` is host-only, rendered as
   a trailing muted column. Members never see balances.
3. **One section, two zones:** a new `ChipsOnTableSection` renders (host-only)
   a "To dispense" zone at top (reusing the existing `HostWithdrawalsSection`
   rows + `dispensedWithdrawalIds` dismissal) then member working-hand rows
   below. The standalone `HostWithdrawalsSection` block in `scrollBody`
   (lines 406-415) is REMOVED; `HostWithdrawalsSection` struct may be kept
   as the dispense sub-zone.
4. **WorkingHand model:** new file `GamesRoom/Models/WorkingHand.swift`
   (Codable, Identifiable, Hashable; Foundation only). Fields:
   `memberId: UUID`, `displayName: String`, `workingHand: Int`,
   `pointsBalance: Int`. snake_case CodingKeys. Must be registered in pbxproj.
5. **Data path:** dedicated RPC `get_event_working_hands(p_event_id)`
   (migration 065), wrapped by a non-throwing
   `CasinoService.loadWorkingHands(eventId:)`.

## Change 1 — Migration 065: get_event_working_hands (NEW file)
`Supabase/migrations/065_event_working_hands.sql`. DROP + CREATE the
function (matches 061 style). RETURNS TABLE cols are the body vars
(`member_id uuid, display_name text, working_hand bigint, points_balance
bigint`). For each room member of the event's room:

```sql
drop function if exists public.get_event_working_hands(uuid);
create function public.get_event_working_hands(p_event_id uuid)
returns table (
  member_id uuid,
  display_name text,
  working_hand bigint,
  points_balance bigint
)
language sql
stable
security definer
set search_path = public
as $$
  select
    m.user_id as member_id,
    u.display_name as display_name,
    coalesce((
      select sum(cw.points_withdrawn)
      from public.casino_withdrawals cw
      where cw.session_id = p_event_id
        and cw.member_id = m.user_id
        and not exists (
          select 1 from public.casino_scans cs
          where cs.session_id = cw.session_id
            and cs.member_id = cw.member_id
            and cs.finalized_at is not null
        )
    ), 0)::bigint as working_hand,
    m.points_balance as points_balance
  from public.room_memberships m
  join public.events e on e.id = p_event_id
  join public.users u on u.id = m.user_id
  where m.room_id = e.room_id
    and exists (
      select 1 from public.room_memberships rm
      where rm.room_id = e.room_id
        and rm.user_id = public.current_user_id()
    )
  order by
    case when m.role = 'host' then 0 else 1 end,
    u.display_name;
$$;

grant execute on function public.get_event_working_hands(uuid) to authenticated;

notify pgrst, 'reload schema';
```

All column refs qualified (061 pattern) to avoid ambiguity. Security definer
+ the `exists` membership check enforce room-member-only reads.

## Change 3 — CasinoService.loadWorkingHands
Add to `CasinoService.swift` in the "Event transactions" / casino section:
non-throwing wrapper following the `getEventTransactions` pattern:

```swift
/// Returns every room member's current working hand for one event.
/// Non-throwing: any failure collapses to `[]` so the section can
/// render its hidden state without an error path.
///
/// Server-side: `get_event_working_hands(p_event_id)`, migration 065.
func loadWorkingHands(eventId: UUID) async -> [WorkingHand] {
    let result: [WorkingHand] = (try? await SupabaseClientProvider.shared
        .rpc("get_event_working_hands", params: [
            "p_event_id": eventId.uuidString
        ])
        .execute()
        .value) ?? []
    self.lastError = nil
    return result
}
```

### 4e. ChipsOnTableSection (new private struct)
Place near `HostWithdrawalsSection` (~line 1945). One section, two zones:

```swift
// MARK: - Chips on the table (V0.51)

/// Per-member working-hand readout for active casino play. Host gets a
/// "To dispense" zone (reusing the V0.47 dispense rows) above the member
/// rows, plus each member's bank balance in a trailing muted column.
/// Members see working hands only — balances are host-visible.
private struct ChipsOnTableSection: View {
    let hands: [WorkingHand]
    let isHost: Bool
    let pendingWithdrawals: [EventTransaction]
    let onDispense: (UUID) -> Void

    var body: some View {
        VStack(alignment: .leading, spacing: Theme.Layout.cardInset) {
            HStack(spacing: 8) {
                Image(systemName: Theme.Icon.circleHexagongridFill)
                    .foregroundStyle(Theme.Palette.accent)
                Text("Chips on the table")
                    .font(Theme.Typography.title)
                    .foregroundStyle(Theme.Palette.primaryText)
            }
            if isHost, !pendingWithdrawals.isEmpty {
                HostWithdrawalsSection(
                    withdrawals: pendingWithdrawals,
                    onDispense: onDispense
                )
                .padding(.top, 4)
            }
            ForEach(hands) { hand in
                HStack(spacing: Theme.Layout.cardInset) {
                    VStack(alignment: .leading, spacing: 2) {
                        Text(hand.displayName)
                            .font(Theme.Typography.body)
                            .foregroundStyle(Theme.Palette.primaryText)
                        Text("Working hand")
                            .font(Theme.Typography.caption)
                            .foregroundStyle(Theme.Palette.primaryText.opacity(0.55))
                    }
                    Spacer()
                    if isHost {
                        Text("\(hand.pointsBalance) bank")
                            .font(Theme.Typography.caption)
                            .foregroundStyle(Theme.Palette.primaryText.opacity(0.55))
                    }
                    Text("\(hand.workingHand) pts")
                        .font(Theme.Typography.body.weight(.semibold).monospacedDigit())
                        .foregroundStyle(Theme.Palette.accent)
                }
            }
        }
        .frame(maxWidth: .infinity, alignment: .leading)
    }
}
```

Keep `HostWithdrawalsSection` as-is (the dispense sub-zone). Note its body
already renders a "Chips to dispense" header + rows; nesting it inside the
"Chips on the table" section is acceptable and preserves the existing
dispense UX. If the double-header reads awkwardly, you may strip the inner
header from `HostWithdrawalsSection` and keep just its rows — record any
such deviation in the SPEC.
