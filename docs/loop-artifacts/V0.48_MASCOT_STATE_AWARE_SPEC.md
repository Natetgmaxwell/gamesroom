# V0.48 — Mascot state-aware social commentary (kanban t_22f77fdb)

## Context

User report: the footer caption has not changed based on the state/context
of the room — the mascot should be aware of the circumstance and what is
happening with the room so it can make social commentary.

Current state (verified in tree):

- `MascotFooterCaption` (RoomDetailView.swift:2617) renders via
  `MascotEngine.footerKind(activeEvent:leaderboard:)` which resolves one of
  **four footer flavours** (roomWelcome / inPlay / roomStale / standings).
  `RoomContext` carries recent winners, leader name, caller rank, event
  count, days quiet (V0.36).
- The 25-voice matrix (5 personality × 5 ideology × 8 kinds = 200 cells)
  interpolates templates (V0.38 rewrote it).
- The `V0State` machine in `RoomDetailView` (line 996) has **10 cases** —
  including `.tonightEvent`, `.inPlay`, `.settleRound`, `.justSettled`,
  `.seasonClose` — but `footerKind` collapses them to 4. The footer does
  **not** narrate the live circumstance the user describes: post-withdrawal
  working hand, someone just won a round, settlement in progress, season
  close / awards.

`MascotEngine.NotificationKind` is only switched on inside `MascotEngine.swift`
(verified: `NotificationDispatcher` uses its own `NotificationKindRaw` enum and
never switches `MascotEngine.NotificationKind`), so adding cases is contained.

## Design

### 1. New `NotificationKind` cases

Add four footer cases (keeps the 4 existing footer cases + 4 briefing cases):

```swift
case tonightEvent        // live, member hasn't withdrawn yet
case inPlayWithWithdrawal// live, member has withdrawn (working hand active)
case settleRound         // live, host finalized (settlement in progress)
case seasonClose         // current season has ended (awards)
```

`.justSettled` (ceremonial recap within 24h) **reuses the existing
`.postPlayRecap` kind** — the recap template already carries the winner
sentence and the V0.36 `footerKind` already mapped settled events to
`.postPlayRecap`. No new cells for it.

### 2. `footerKind` extension (state-aware resolution)

New signature (defaulted params keep existing call sites compiling):

```swift
static func footerKind(
    activeEvent: Event?,
    leaderboard: [LeaderboardEntry],
    now: Date = Date(),
    withdrawnAmount: Int = 0,
    currentSeason: Season? = nil
) -> NotificationKind
```

Resolution order (first match wins — mirrors the `V0State` precedence in
`RoomDetailView`):

| Condition | Kind |
|---|---|
| `currentSeason?.status == .ended` | `.seasonClose` |
| `activeEvent?.settledAt != nil` | `.postPlayRecap` |
| `activeEvent != nil`, live, `hostFinalized` | `.settleRound` |
| `activeEvent != nil`, live, `withdrawnAmount == 0` | `.tonightEvent` |
| `activeEvent != nil`, live, `withdrawnAmount > 0` | `.inPlayWithWithdrawal` |
| `activeEvent != nil` (upcoming) | `.briefingOnCreate` |
| `leaderboard.isEmpty` | `.roomWelcome` |
| last play > 14 days ago | `.roomStale` |
| otherwise | `.standings` |

### 3. `RoomContext` extension (defaulted — existing call sites compile)

```swift
struct RoomContext {
    // existing fields ...
    let withdrawnAmount: Int?   // NEW, default nil  → {working_hand}
    let lastWinnerDelta: Int?   // NEW, default nil  → {last_delta}
    let seasonDaysLeft: Int?    // NEW, default nil  → {season_days_left}
}
```

`{last_winner}` reuses the existing `recentWinnerNames.first` (no new field).
Add the three new fields to the explicit init with defaults, keeping the
`NotificationDispatcher` 4-arg construction compiling.

**Settlement-state fact:** carried by the kind (`.settleRound`) rather than a
context field — the template already differs by kind, so a separate
`isSettlementInProgress` field would be dead data.

**`{season_days_left}` caveat:** the `Season` model has no planned end date
client-side (only `endedAt` once closed), and `.seasonClose` fires only when
the season is already ended. So `seasonDaysLeft` is passed as `nil` from the
view and `{season_days_left}` stays in the nil-preserving set — any template
sentence referencing it drops cleanly. The `seasonClose` cells below do **not**
reference it (they use `{leader}` / `{winner}` / `{room}`). Declared so the
placeholder contract is future-proof for an "approaching season end" nudge.

### 4. Placeholder contract extension

Add to the nil-preserving + sentence-drop set:
`{working_hand}`, `{last_delta}`, `{season_days_left}`.
`{last_winner}` reuses `recentWinnerNames.first` (already nil-preserving via
`{winner}`'s source). The sentence-drop pass in `interpolate` removes any
sentence still containing a `{` — so the new optional placeholders are
nil-safe automatically.

### 5. New data derivation (pure, testable)

```swift
/// Points delta of the most recent winner across rounds, or nil when
/// no round has a winner. Walks rounds newest-first (roundIndex DESC)
/// and returns the first winner entry's pointsDelta.
static func lastWinnerDelta(rounds: [EventRound]) -> Int?
```

### 6. `buildLLMPrompt` additions

After the existing V0.36 context lines, when present:

```
Working hand: {withdrawnAmount}      // only when > 0
Last winner: {recentWinnerNames.first}
Last winner delta: {lastWinnerDelta}
Season days left: {seasonDaysLeft}   // nil today — declared for future use
```

And the `switch kind` gains the four new "Message type:" lines. This is where
`{last_delta}` and `{season_days_left}` earn their keep: the template cells do
not reference them (no cell needs a delta or a season-countdown sentence yet),
so they stay in the nil-preserving set as a no-op on the template path, but the
LLM path reads them as grounded context and can reference a winner's delta or
an approaching season end. `{working_hand}` IS referenced by the
`.inPlayWithWithdrawal` cells.

### 7. View changes (`MascotFooterCaption`)

New props passed from the parent call site (RoomDetailView.swift:441):

- `withdrawnAmount: Int` (the member's `casinoWithdrawn` @State)
- `currentSeason: Season?` (from `roomService.cachedCurrentSeason`)

The footer passes these into `footerKind(...)` and into `RoomContext`:

```swift
context: .init(
    // existing fields ...
    withdrawnAmount: withdrawnAmount > 0 ? withdrawnAmount : nil,
    lastWinnerDelta: MascotEngine.lastWinnerDelta(
        rounds: roomService.cachedEventRounds(eventId: activeEvent?.id ?? UUID())
    ),
    seasonDaysLeft: nil   // no planned season end client-side — see §3
)
```

Call site passes `withdrawnAmount: casinoWithdrawn, currentSeason: currentSeason`.

## 8. Template matrix (4 new kinds × 25 cells = 100 new cells — transcribe VERBATIM)

Transcribe these cells **verbatim** into `templateFor`. Voice directions are
pinned by V0.38 (see the `templateFor` doc comment). All cells are 1–3 short
sentences, ≤ 200 chars fully populated, ≤ 1 `!` (unhinged additionally bans
ALL-CAPS, keeps ≤ 1 `!`).

Voice directions (V0.38 pinned): professional = declarative, zero `!`, no
air quotes, no "we", no digs; friendly = warm/inclusive, one `!` max;
snarky = pointed-but-kind, one dig then a fair line, second-person group
address, no air quotes; sarcastic = dry irony, air quotes, one irony per
body, no ALL-CAPS; unhinged = normal case (no ALL-CAPS), stream-of-conscious,
one non-sequitur, one `!` max. Ideology: order trusts host, centrist reads
room, trickster shuffles standings, anarchist refuses authority, apocalypse
is light doom.
