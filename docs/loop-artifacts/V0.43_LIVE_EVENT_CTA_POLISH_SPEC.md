# V0.43 — Live-event CTA polish: withdraw-to-play gating, CAH settle gating, CTA at top

## Goal
Polish the live-event call-to-action flow per user feedback. The member must
withdraw points before they can play casino games or settle their hand; the
withdraw CTA should read "Withdraw to play"; after withdrawal the state moves
to in-play and the scan CTA appears; CAH settle is gated to live events; the
CTA hero sits at the top of the scroll.

## Current state (verified in tree)
- `RoomDetailView` V0State machine:
  - `.tonightEvent` = live && `casinoWithdrawn == 0` → WitnessSlot with
    `cta: isCAH ? .scan : .withdraw` (casino shows withdraw) ✓
  - `.inPlay` = live && `casinoWithdrawn > 0` → WitnessSlot with
    `cta: isCAH ? .scan : .withdraw` — **BUG: casino shows `.withdraw` even
    after the member has withdrawn. Should be `.scan`.**
  - `.settleRound` = live && hostFinalized → `cta: .scan` ✓
- `WitnessSlot` (RoomDetailView.swift ~line 1364) renders the withdraw button
  with text `"Withdraw chips"` → needs `"Withdraw to play"`.
- `WithdrawChipsSheet` (WithdrawChipsSheet.swift) has a stepper (10...balance,
  step 10) for amount selection ✓. On successful `save()` it calls `dismiss()`
  but has NO `onDone` callback — so `casinoWithdrawn` is never refreshed and
  the state stays `.tonightEvent` instead of moving to `.inPlay`.
- `activeSlot` is the first child of the `scrollBody` VStack → CTA hero already
  renders at the top, above standings/packs/members ✓.
- CAH scan CTA only appears in live states (`.tonightEvent`/`.inPlay`/
  `.settleRound`); pre-play uses `BriefingSlot` → CAH settle already gated to
  live ✓.

## Changes

### 1. RoomDetailView.swift — `.inPlay` casino CTA → `.scan`
In the `.inPlay` case (~line 541), change:
```swift
cta: isCAH ? .scan : .withdraw,
```
to:
```swift
cta: .scan,
```
Rationale: `.inPlay` means the member has withdrawn (casinoWithdrawn > 0), so
the casino member CTA is now "Scan your chips", not "Withdraw to play". The
`isCAH` local is still used for `scanTitle`, so keep the `let isCAH` line.

### 2. RoomDetailView.swift — WitnessSlot withdraw button wording
In `WitnessSlot` (~line 1367), change the withdraw button label:
```swift
Text("Withdraw chips")
```
to:
```swift
Text("Withdraw to play")
```

### 3. WithdrawChipsSheet.swift — add `onDone` callback
Add a stored closure property:
```swift
var onDone: (() -> Void)? = nil
```
In `save()`, after the successful `withdraw(...)` call and before/after
`dismiss()`, invoke `onDone?()`. Keep `dismiss()` so the sheet closes.

### 4. RoomDetailView.swift — pass `onDone` to WithdrawChipsSheet
In the `.sheet(item: $withdrawSheetEvent)` binding (~line 252), pass:
```swift
WithdrawChipsSheet(eventId: event.id, roomId: room.id, onDone: {
    Task { await refresh(force: true) }
})
```
`refresh(force: true)` reloads `loadMyOpenWithdrawalIfNeeded`, which sets
`casinoWithdrawn` to the new withdrawal amount → state transitions from
`.tonightEvent` to `.inPlay` → scan CTA appears.

## Acceptance criteria

- Withdraw sheet lets member pick an amount (stepper) — already present.
- After withdraw, state moves to `.inPlay` and "Scan your chips" CTA appears.
- CAH scan CTA only when event is live — already gated.
- Tests + parse-checks green (`./build-and-run-tests.sh`).
