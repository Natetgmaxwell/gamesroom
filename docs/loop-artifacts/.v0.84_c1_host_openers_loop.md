## C1 requirements (locked)

Pre-night, on the host's iPad only (the member never sees it), show one
opening line per attending member — a short, specific, genuine opener drawn
from the social-preferences + chair-card data. Carnegie Ch 2.3 (name =
sweetest sound) + 4.7 (reputation to live up to).

The line is a SUGGESTION, not a script. The host can use it or ignore it.
The system provides the raw material; the host delivers the move in their
own voice at the table.

Mascot boundary (locked): the suggestion is mascot-framed ("Felty
suggests: …"), but the host DELIVERS it in the host's own voice. The host
is the mascot's human proxy, not its puppet.

Zero new tables — the per-member social-preferences surface ALREADY
EXISTS: `room_memberships.preferences_social` /
`preferences_conversation_prompt` / `preferences_default_set` (migrations
026/059/066), surfaced to iOS via `get_room_members` RPC and decoded into
`Member.socialPreference: SocialPreference` (GamesRoom/Models/Member.swift).
Do NOT add a member_social_preferences table. Do NOT add any migration.

## Locked decisions for this loop

1. **Derivation lives in a new Foundation-only model file**
   `GamesRoom/Models/HostOpenerSuggestion.swift` — pure, testable in
   main.swift (no SwiftUI import). Input: member + rsvp + leaderboard +
   now. Output: one mascot-framed opener line per attending member.
2. **Render site**: `RoomDetailView.scrollBody` — a host-only section
   card, placed directly under `activeSlot`, gated on
   `isHost && activeEvent != nil && activeEvent.playedAt > Date()`
   (pre-night only). One row per CLAIMED RSVP (attending = claimed).
   Ineligible/edge members still get a row (name-forward fallback) —
   every attending member gets exactly one opener.
3. **Priority ladder for the opener line** (first match wins):
   a. Member's own `socialPreference.socialText` (non-empty, non-default)
      → mirror their stated preference back, name-first.
   b. `socialPreference.conversationPrompt` (non-empty) → open on their
      stated conversation topic, name-first.
   c. First night (`sessionsPlayed == 0`) → welcome-by-name, no history.
   d. Won last session (`lastSessionDelta > 0`) → Ch 4.7 reputation:
      name + the win to live up to.
   e. Long tenure (`sessionsPlayed >= 5`) → name + reliability.
   f. Fallback → plain name-forward greeting.
   All lines ≤ ~140 chars, specific, genuine; no stats-dump, no
   blanket flattery. "{mascot} suggests:" prefix is applied by the
   VIEW (mascot name is room state, not model state).
4. **Host-only guarantee**: the section renders only when `isHost`;
   no member-facing surface references HostOpenerSuggestion. The data
   source (`get_room_members`) is pre-existing RPC — no schema change,
   so no new member-visible leak path.
5. **Tests**: add cases to main.swift (Foundation runner):
   - each ladder branch produces the expected line
   - default/empty socialText does NOT hit branch (a)
   - claimed-only filtering (declined/unclaimed excluded)
   - determinism + length cap
6. **pbxproj**: new file HostOpenerSuggestion.swift needs manual
   registration (objectVersion 56, deterministic A… IDs). Next free
   fileRef IDs: 4B0/4B1 series; next free build-file IDs: EF/F0
   series — VERIFY uniqueness by grep before inserting. Insert in the
   Models group children list (alphabetical neighborhood of
   HostOpenerSuggestion: after EventTransaction.swift, before
   InviteRewards.swift) and in the Sources build phase.
   Run `python3 scripts/verify-xcode-project.py` after.
