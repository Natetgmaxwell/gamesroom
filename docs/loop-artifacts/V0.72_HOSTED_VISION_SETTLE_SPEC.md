# V0.72 — Hosted Vision Settle Spec (MiniMax)

Status: Approved-greenlit 2026-08-15 (user directive: "use the minimax analyse
image for chip and card counting — don't rely on on-device intelligence; don't
let the user adjust what the vision model has seen"). Defaults below run unless
overridden in-chat; overrides land as task amendments.

## Problem

1. On-device `ChipSegmentationDetector` count MAE ~6 — wrong tallies on real tables.
2. Member-editable counts (steppers on both scan sheets) are a cheating avenue.
3. The bigger hole: the member *app* posts the count. `record_member_scan` /
   `record_cah_tally` accept a client-supplied number — a crafted RPC call can
   post anything regardless of which detector ran.
4. V0.8's hosted-vision design (migration 027) was built-but-disconnected: the
   DB accepts `minimax_vision`, the app has `VisionProvider.hosted`, nothing
   calls MiniMax. Its per-room `vision_api_key` is also member-readable via
   security-definer `get_casino_config` — dead design, do not revive.

## Objective

MiniMax vision counts chips (casino settle) and black cards (CAH tally) from
the member's captured photo. The count is **authoritative**: members see it,
cannot adjust it, and the recording happens server-side from the model output.
Anti-cheat posture: the member client can no longer write a count, ever.

## Architecture

```
Member app                Supabase Edge Function           MiniMax
─────────                ──────────────────────           ────────
capture frame  ──JPEG──▶  scan-settle(kind)  ──prompt──▶  vision model
no count posted          · verify member JWT               (image in,
                         · rate-limit attempts              count out)
                         · hash JPEG, discard bytes
                         · call record_member_scan /        ◀── count
                           record_cah_tally as service role
show authoritative ◀────  { count, breakdown, hash, attempt# }
result (read-only)
```

- **One edge function** `supabase/functions/scan-settle/index.ts`, `kind:
  "chips" | "cards"` discriminator. MiniMax key lives ONLY in edge secrets
  (`MINIMAX_API_KEY`, `MINIMAX_VISION_MODEL`) — never in `casino_room_config`,
  never on a client. Migration 027's `vision_api_key` column stays but is
  unused; docs mark it deprecated.
- **MiniMax call**: `POST https://api.minimax.io/v1/chat/completions`
  (same host the MascotEngine already uses), image as base64 data-URL content,
  one-shot counting prompt per kind. Exact vision model name verified against
  current MiniMax docs at implementation; recorded in the commit. Chips prompt
  returns per-color stack breakdown + total points using the room's chip value
  map (fetched server-side); cards prompt returns a single count.
- **Recording**: edge function calls the existing RPCs via service role with
  an explicit member id. New migration `069_hosted_scan_authority.sql`:
  - `record_member_scan` / `record_cah_tally` gain optional `p_member_id`,
    honored only when caller is service role.
  - When the room's `vision_provider = 'minimax_vision'`, member-role calls to
    both RPCs are REJECTED (only service role may record). When `on_device`
    (legacy), behavior unchanged.
  - `vision_provider` default flips to `minimax_vision` for new casino rooms.
  - New append-only `scan_attempts` log: member, event, kind, count, photo
    hash, created_at. Every model count lands here — re-scan history is
    auditable by the host.
- **Client rework** (`ChipScanSheet`, `CAHCardScanSheet`): capture → upload →
  read-only result. Steppers deleted. "Re-scan" replaces the previous attempt
  (latest wins). Errors: model-declined ("couldn't read — retake"), offline,
  rate-limited. `ScanConfidenceGate` path removed from both sheets (hosted
  counts carry no calibrated confidence). `ChipSegmentationDetector` stays in
  the repo (host probe tool uses it); sheets stop calling it.
- **Fallback** (no camera / model down / member can't scan): host-side manual
  count entry on the settle screen (`DetectionSource.manual` already exists).
  The member never types numbers. If a host manual-entry control is missing
  today, add it to the settle screen — bounded, not a redesign.
- **Privacy reversal — NAMED**: F-CAS-03 said photos stay on-device. This
  rework sends the JPEG to MiniMax's API. Photo bytes still never persist
  server-side (edge function hashes and discards); the hash travels for
  dispute matching, as today. App copy updates: "On-device" → accurate label;
  scan-sheet privacy line updated.

## Anti-cheat summary

| Avenue | Before | After |
|---|---|---|
| Stepper edit | open | gone |
| Crafted RPC with own number | open | rejected (provider-gated, service-role-only) |
| Re-scan farming | n/a | capped (5 attempts/event), all attempts logged, host-visible |
| Key theft | per-room key member-readable | one key, edge secret only |

## Boundaries

- **Never**: MiniMax key outside edge secrets; member-writable counts when
  provider is hosted; photo bytes persisted anywhere server-side.
- **Ask first**: changing any RPC signature beyond the additive pattern above;
  touching non-scan surfaces.
- **Always**: additive migrations only; every RPC change named in Swift
  docstrings with its migration; parse-check + verify-xcode-project + full
  test suite green per slice; xcodebuild for iOS slices.
