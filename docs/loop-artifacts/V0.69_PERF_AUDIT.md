# V0.69 — Performance audit: kill multi-second hang times

## Problem (user report 2026-08-14)

"the hang time is routinely in the thousands of milliseconds" — the room
detail page routinely takes multiple seconds to settle after open,
pull-to-refresh, and sheet dismiss.

## Measured baseline (2026-08-14, this audit — CLT host, live Supabase ap-southeast-1 via Cloudflare)

Network path measurements (curl, unauthenticated RPC — connection cost is the
suspect, not server compute):

- Cold connection per RPC: DNS ~5–30ms + TCP ~20–60ms + TLS ~50–96ms ≈
  75–185ms before the request bytes leave. 3 cold samples: 456ms / 82ms /
  79ms total (first includes DNS cache miss).
- Warm keep-alive (HTTP/2, same connection): r2=24ms, r3=24ms, r4=23ms.
- Warm vs cold delta: **~55–80ms wasted per RPC** when connections are not
  reused.
- Server supports HTTP/2 (curl reports http_version=2).

### RPC fan-out per `refresh(force: true)` (static count from code)

Every pull-to-refresh, every sheet-dismiss (`onDone:`), and post-action
re-fetch runs `refresh(force: true)` which fires ~15 parallel loads.
Force=true bypasses the 30s TTL cache on every TTL-gated load:

| # | Load | RPC(s) | Cached? |
|---|------|--------|---------|
| 1 | loadActiveIfNeeded | get_active_event | TTL 30s (force-bypassed) |
| 2 | loadLeaderboardIfNeeded | get_room_leaderboard | TTL 30s (force-bypassed) |
| 3 | loadAttestations | close_stale_attestations (WRITE) + get_my_open_attestations | **UNCACHED, every refresh** |
| 4 | loadBriefingIfNeeded | get_briefing_summary | cached-if-present (force-bypassed) |
| 5 | loadRSVPIfNeeded | get_current_member_rsvp (see RoomStore) | always re-fetch comment |
| 6 | loadMembersIfNeeded | fetchRoomMembers | always re-fetch comment |
| 6b| loadHostWithdrawalsIfNeeded (host only) | get_active_event (guard) + get_event_transactions | **UNCACHED** |
| 6c| loadWorkingHandsIfNeeded | get_active_event (guard, V0.62.1) + get_event_working_hands | **UNCACHED** |
| 7 | loadSeasonIfNeeded | get_current_season → (+ awards, + history serial) | TTL (force-bypassed) |
| 8 | loadSystemEvents | get_room_system_events | TTL 30s (force-bypassed) |
| 9 | loadRSVPGridIfNeeded | get_event_rsvps | TTL 30s (force-dismissed) |
| 10| loadPackConfigsIfNeeded | fetchRoomPackConfigs | TTL (force-bypassed) |

Cold open (empty caches): 17+ RPCs. Steady-state forced refresh (host, casino):
15–17 RPCs. Of those, 7 are unconditional/uncached regardless of the force
flag: attestations (2 incl. a write RPC), hostTransactions, workingHands,
members, rsvp, and the activeEvent guard-fetches can stack.

### Supabase client configuration (SupabaseClient.swift:83-86)

```swift
config.httpAdditionalHeaders = ["Connection": "close"]
```

This disables keep-alive entirely and forces HTTP/1.1 semantics: **every
RPC pays the full TCP+TLS handshake** (~55–80ms measured) to ap-southeast-1
via Cloudflare edge, and `httpMaximumConnectionsPerHost = 6` serializes
connection churn under the 15-load parallel fan-out. This single line is the
single biggest structural latency source: 15 RPCs × ~60ms handshake ≈ 0.9s
of pure handshake overhead per forced refresh, before any server time.

### Cold-load race: triple `get_active_event` (RoomDetailView.refresh)

On cold open (all caches empty), `loadBriefingIfNeeded`,
`loadHostWithdrawalsIfNeeded`, and `loadWorkingHandsIfNeeded` all check
`cachedActiveEvent == nil` and call `loadActiveEvent(force: false)` in
parallel. RoomService.loadActiveEvent has no single-flight: 3 concurrent
`get_active_event` RPCs fire for the same room. +2 redundant RPCs × 2 views
of handshake cost, and they serialize behind the 6-connection cap.

### Config plumbing bug (confirmed, two prior verification tasks)

`GamesRoom/Config.xcconfig` writes `SUPABASE_URL = "https://…"` — in
xcconfig format `//` starts a comment **even inside quotes**, so the value
arrives in Info.plist as `"https:` (leading quote literal). `URL(string:)`
returns nil → compiled fallback engages (same URL, zero latency cost —
verified the fallback URL string is byte-identical to the xcconfig URL).
Zero latency impact but a correctness landmine: any future URL change in
xcconfig would be silently ignored. MINIMAX_API_KEY is quoted too — quotes
arrive literally in the key value → mascot LLM voice silently broken since
the quotes became part of the key.

**Why not pbxproj**: project.pbxproj is committed — the anon key and
MiniMax key must stay in the gitignored xcconfig. And the URL cannot be
written in xcconfig at all (`//` is always a comment start, no escape).

**Fix**: `Config.xcconfig` defines `SUPABASE_HOST` (hostname only — no
`//`, safe unquoted) plus the keys (anon key already unquoted; unquote
MINIMAX_API_KEY — quotes are literal chars in xcconfig values, so the
quoted key currently ships with quote bytes that break the LLM auth).
`Info.plist` composes: `https://$(SUPABASE_HOST)` (mixed literal +
`$(VAR)` expansion is standard in Info.plist values). SupabaseClient.swift
gains a `host != nil` validation so a missing SUPABASE_HOST degrades to
the compiled fallback instead of a hostless URL.

## Fixes (top-3 + hygiene)

### Fix 1 (biggest): restore connection reuse + HTTP/2
SupabaseClient.swift — remove `Connection: close` header; keep
`httpMaximumConnectionsPerHost = 6` (HTTP/2 multiplexes all RPCs over one
connection); consider `timeoutIntervalForRequest = 15` kept as-is.

### Fix 2: single-flight + TTL cache the uncached loads
- `CasinoService.getMyOpenAttestations()`: gate the lazy
  `close_stale_attestations` write behind a 60s in-memory throttle (write
  at most once per minute), and TTL-cache the read (30s) with
  force-bypass on pull-to-refresh only.
- `loadWorkingHands` + `getEventTransactions`: add 30s TTL cache in
  CasinoService keyed by eventId (server is source of truth after actions
  via explicit invalidation on withdraw/settle/dispense mutations).
- `loadActiveEvent` in RoomService: add single-flight — concurrent callers
  share one in-flight `get_active_event` task per roomId.

### Fix 3: xcconfig `//`-truncation
`Config.xcconfig`: replace the `SUPABASE_URL` line with unquoted
`SUPABASE_HOST = bnrgkdcluopicqdpmrtu.supabase.co`; unquote
MINIMAX_API_KEY. `Info.plist`: `SUPABASE_URL` =
`https://$(SUPABASE_HOST)`. `SupabaseClient.swift` `readConfig`:
treat a value with no `.` or missing host as invalid → fallback.
Verify built Info.plist on Mac Studio (plutil -extract on the built
app bundle).

### Hygiene: instrumentation
`PerfSignposts` (os_signpost) at: refresh begin/end, each load's network
duration. Keep permanently (os_signpost Instruments-compatible, zero
release cost). Add `[GamesRoom]` print timing lines DEBUG-only for log
stream capture.

### Hygiene: TEMP verify hooks removal
After measurement, remove the TEMP V0.62 verification hooks in
ContentView.swift + RoomPage.swift (auto-push + token injection).

## Measured results (Mac Studio, iPhone 17 Pro sim, live ap-southeast-1 DB)

### BEFORE (baseline, build 9511320 + instrumentation)

Cold open (`.task`, force=false), 3 runs — 9-10 RPCs, wall 1.2-1.4s:

```
rpc get_active_event 204ms      <- race: fires 3x (204/403/248)
rpc get_active_event 403ms
rpc get_active_event 248ms
rpc get_room_leaderboard 229ms
rpc close_stale_attestations 248ms   <- WRITE rpc, every refresh
rpc get_room_system_events 258ms
rpc get_event_working_hands 151ms
rpc get_season_history 147ms
rpc get_my_open_attestations 151ms   <- serial after the write
loadAttestations 409ms               <- write+read serialized
loadWorkingHands 175ms
refresh end                          <- ~1.2s total
```

CFNetwork-level: per-RPC server latency 140-420ms dominates (handshake
reuse already active); the slow cluster 385-415ms = write RPCs.

### AFTER (build d11dcab + 7ab633e single-flight cache-write fix)

Steady-state cold open, 3 runs — 8 RPCs, critical path ~600ms:

```
rpc get_active_event 237ms       <- x1, single-flight (was x3)
rpc close_stale_attestations 208ms  <- first refresh only; 60s throttle
rpc get_room_system_events 261ms
rpc get_room_leaderboard 261ms
rpc get_my_open_attestations 143ms
rpc get_season_history 148ms
rpc get_event_working_hands 166ms   <- join-race fixed; fires correctly
loadAttestations 353ms              <- first refresh only; 30s TTL after
loadWorkingHands 167ms
refresh end                         <- ~600ms critical path
```

### Deltas

| Metric | Before | After |
|---|---|---|
| RPCs per cold refresh | 9-10 | 8 (first), ~5 within TTL windows |
| get_active_event per cold open | 3 | 1 |
| close_stale_attestations write | every refresh | 1x per 60s |
