# V0.37 — Seat roster social proof (spec)

## Context

User feedback: "The rooms page, when there is an event, should tell you who
else has claimed a seat for said event. This gives people social proof."

gbrain MVP scope names social proof **load-bearing**: "Spectator view for
non-host members — cheap to ship, valuable for social proof, and a load-bearing
MVP feature not a nice-to-have."

The detail page's briefing card already renders the seat grid (initials per
claimed member) and the `BriefingSeatCount` counts line — but neither the
rooms LIST nor the briefing card surface member NAMES. The data exists:
`event_rsvps` rows reach the briefing via `EventRSVP` (displayName + state),
and `RoomService.eventRSVPsByEvent` caches them per event.

## Locked decisions (do not re-litigate)

1. **Caption copy.** One-line, footer-caption weight, claimed members only:
   - 0 claimed → no caption (silent)
   - 1 claimed → `Sarah has claimed a seat`
   - 2 claimed → `Sarah and Mike have claimed seats`
   - 3+ claimed → `Sarah, Mike +N more have claimed seats` (first two names in
     input order, `+N` = remaining count)
   - Names are trimmed, empties dropped.
2. **Formatter location.** New `SocialProof` enum **inside
   `GamesRoom/Models/EventRSVP.swift`** (pure Foundation, compiled by the test
   runner). No new Swift files anywhere — pbxproj must not change.
3. **List-side data flow.** New `RoomService.loadRoomsSocialProof() async`
   iterates `self.rooms`: load active event if uncached; if the event is
   pre-play (`startedAt == nil`), load RSVP rows when the event's cache is
   empty. Called from `RoomPage` `.task` and `.refreshable` right after
   `refresh()`. Cache-hit short-circuits. Side effect (accepted): the
   active-session dot on list rows now populates on first load instead of
   only after opening the room — strictly better, matches US-06.
4. **List row subtitle.** The static `Tap to open` line is REPLACED by the
   social-proof caption when one exists, else `Tap to open` stays. One
   subtitle line per row — no stacked caption-weight lines. Applied to the
   iPhone list rows AND the iPad sidebar rows (both are the rooms list).
5. **Hero card.** No social proof on the last-viewed hero — it is a resume
   accelerator, not a roster surface.
6. **Detail briefing.** Caption line added below the seat grid in
   `BriefingSlot` (grid only renders when rsvps are loaded, so the caption
   rides the same precondition). `BriefingSeatCount` counts line unchanged.
   The grid's initials stay; the caption supplies full names (scope item 2).
7. **Pre-play only.** `startedAt == nil` gates the caption on both surfaces.
   In-play and settled events show no roster line.
8. **Theme discipline.** Caption uses `Theme.Typography.caption` +
   `Theme.Palette.primaryText.opacity(0.55)` — the repo's standard secondary
   text. No new tokens, no hardcoded colors/fonts/sizes.
9. **No backend change.** No migration, no RPC change. `get_event_rsvps`
   already returns displayName + state.
