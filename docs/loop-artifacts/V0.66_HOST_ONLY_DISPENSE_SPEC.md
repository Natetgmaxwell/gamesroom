# V0.66 — Strip "Chips withdrawn" section to host-only "Chips to dispense" cards

## Goal

USER (2026-08-14): "we can now remove the chips withdrawn heading, and only have
the chips to dispatch cards for hosts."

The V0.51/52 per-member working-hand readout ("Chips withdrawn" header + caption +
per-member rows) is now GONE. During casino play, members see NO chips section at
all; hosts see ONLY the "Chips to dispense" cards (member name + amount +
Dispensed) when pending withdrawals exist.

## Design decisions (owner: orchestrator — do not relitigate)

1. **KEEP the workingHands load, model, and RPC.** `myWorkingHand` derives from
   `workingHands` (V0.62), and `loadWorkingHandsIfNeeded` feeds `casinoWithdrawn`
   which drives the state machine (`.tonightEvent`/`.inPlay`) and the sheets,
   mascot, and witness badge. Removing the load would strand the state machine.
   Only the UI render is stripped.
2. **scrollBody gate becomes host-only.** Render `HostWithdrawalsSection` directly
   (reuse the existing struct) when `isCasinoPlayActive && isHost && !pendingWithdrawals.isEmpty`.
   Drop the `workingHands.contains { $0.workingHand > 0 }` condition and the
   member-visible path entirely.
3. **Delete `ChipsOnTableSection` struct.** Its only job was the header/caption +
   per-member rows + wrapping the host dispense zone. The host dispense zone is
   now rendered directly. No dead code left behind.
4. **Keep `HostWithdrawalsSection` exactly as-is** (member name + amount +
   Dispensed tap). Dispensed acknowledge still works (local `dispensedWithdrawalIds`).
5. **Do NOT touch migration 065, WorkingHand.swift, CasinoService, or the RPC.**
   No schema change. No pbxproj change (no new files).
