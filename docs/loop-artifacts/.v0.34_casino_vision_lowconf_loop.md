# V0.34 casino-vision low-confidence gate (self-contained)

You are implementing the low-confidence re-scan gate for the Casino chip-scan flow in the Games Room repo. Work in the current directory.

## Context

The on-device chip-scan flow is already wired (commits 017fc1a, f470f55): `GamesRoom/Views/ChipScanSheet.swift` opens the camera, runs `ChipSegmentationDetector` (GamesRoom/Models/ChipSegmentationDetector.swift) on the captured frame, shows per-stack results with editable counts, and records via `CasinoService.submitMemberScan`. The detector's `confidence` is a frame-coverage proxy normalized to [0,1] (`min(1, areaFraction * 20)`); `confidenceAvg` is the mean across stacks.

The missing piece: when the scan's `confidenceAvg` is low, the sheet currently advances straight to the confirm view. It must instead prompt a re-scan with lighting guidance.

## Task

1. Add a pure, Foundation-only confidence gate to `GamesRoom/Models/ChipSegmentationDetector.swift` (same file as the detector — do not create a new file). Shape: a small enum or struct, e.g. `ScanConfidenceGate`, with:
   - A named rescan threshold constant (0.3).
   - A pure function `shouldPromptRescan(confidenceAvg: Double) -> Bool` returning true strictly below the threshold, false at/above it. No UI, no Vision imports — must compile in the Foundation test runner.
   - A one-line doc comment explaining the threshold rationale: confidence is a frame-coverage proxy, so below 0.3 the stacks occupy <1.5% of the frame and the height-based count estimate is unreliable.

2. Wire the gate into `GamesRoom/Views/ChipScanSheet.swift`:
   - In `processFrame`, after `recomputeTotals()`: when `ScanConfidenceGate.shouldPromptRescan(confidenceAvg:)` is true, do NOT set `showConfirm = true`. Instead set a new low-confidence state so the camera view stays up.
   - Camera view: when the low-confidence state is active, show a guidance banner in place of the normal "Tap shutter to scan" caption — text along the lines of "Low confidence — move closer, improve lighting, and try again." Keep the shutter available for re-scan.
   - Add a secondary "Review result anyway" button under the banner that advances to the confirm view (the per-stack steppers are the user-attestation fallback, so forcing through is safe). Tapping it clears the low-confidence state and sets `showConfirm = true`.
   - The existing Re-scan button in the confirm view already resets state; make sure it also clears the new low-confidence state.
   - Do not change the "No chip stacks found" path (empty stacks → error message, stay on camera view).

3. Add one Foundation test in `./main.swift` (repo root) in the existing F-CAS-02 section (near line 920, after the PhotoHash test): `ScanConfidenceGate` returns true below 0.3, false at 0.3 and above, and false for a perfect 1.0. Follow the existing `runner.run("name") { ... }` + `assertTrue`/`assertFalse` helper style.
