the app does not ask for Sign in with Apple every time. The user already has a
valid session in the keychain; `AuthService.loadCurrentUser()` exists and does

4. **Design shape (from the spec, implement exactly):**
   - Add `@State private var isRestoringSession = true` to `ContentView`.

     `ProgressView()`, no new tokens/colors) while restoring; the existing

     `{ isRestoringSession ? false : auth.currentUser == nil }` — sheet never
     shows during restore; shows only when restore finished with no user.
   - Keep `.tint(Theme.Palette.accent)`.
   - Update the file's header doc comment (lines ~20-27) so it describes the
     restore-on-launch flow instead of only the currentUser-nil gate. Match the
     existing ponytail/comment style. No comments that restate code.
5. **No dead code, no TODOs.** Match the file's existing conventions.
6. **Behavior contracts that must not regress:**
   - Sign-out (currentUser → nil, isRestoringSession already false) still
     re-presents the sheet.
   - First launch with no session: brief splash, then sheet (loadCurrentUser
     fails fast on missing keychain session).
   - Valid session: splash, then TabView, no sheet.
