# V0.62 — Drive state machine from workingHands (stuck "Withdraw to play" CTA)

## Goal

User screenshot (2026-08-14 11:20): Test Room `.tonightEvent` — CTA says
"Withdraw to play" even though the host ALREADY withdrew 100 pts. The V0.51
"Chips withdrawn" section renders correctly with per-member working hands
(Nathan 100, DevSim 0), so `get_event_working_hands` works. But the state
machine never advances past `.tonightEvent`, so the user never sees the
settle/vision flow.

## Root cause

- `RoomDetailView.state` branches `isLive && casinoWithdrawn == 0 -> .tonightEvent`.
- `casinoWithdrawn` comes ONLY from `loadMyOpenWithdrawalIfNeeded` ->
  `get_my_open_withdrawal` RPC -> collapses to 0 on any failure/empty.
- For the host, `get_my_open_withdrawal` returns empty on the live DB.
- `get_event_working_hands` (migration 065) WORKS but the state machine ignores it.

## Current state (verified in tree)

- `@State private var casinoWithdrawn: Int = 0` (RoomDetailView.swift:73).
- `@State private var workingHands: [WorkingHand] = []` (:81) loaded by
  `loadWorkingHandsIfNeeded()` (:984) via `casinoService.loadWorkingHands`.
- State branch (:516): `if isLive && casinoWithdrawn == 0 { return .tonightEvent }`,
  then `if isLive { return .inPlay }`.

  - :366 SettleCasinoSheet host manual `withdrawn:` (hostManualSettleSheetEvent)

  - :949/:953 `loadMyOpenWithdrawalIfNeeded` (loader body)

  `loadMyOpenWithdrawal(eventId:)?.pointsWithdrawn ?? 0`.
- `refresh()` (:824) calls `withdrawalLoad` = `loadMyOpenWithdrawalIfNeeded()`.

## Design decisions (owner: orchestrator — do not relitigate)

1. **Single source of truth = workingHands.** Derive the caller's working hand
   as a computed property:
   `private var myWorkingHand: Int { workingHands.first(where: { $0.memberId == currentUserId })?.workingHand ?? 0 }`
   `currentUserId` is already `UUID?`. `WorkingHand.memberId` is `UUID`, so
   compare `$0.memberId == currentUserId` (Swift allows UUID? == UUID).
2. **State trigger swaps `casinoWithdrawn` -> `myWorkingHand`:**
   - `isLive && myWorkingHand == 0 -> .tonightEvent`
   - `isLive -> .inPlay` (myWorkingHand > 0)
   - Keep `.settleRound` (hostFinalized) precedence unchanged.
3. **Keep `casinoWithdrawn` @State but feed it from workingHands** so the
   sheet bindings (:319/:349/:366), MascotFooterCaption (:475), and WitnessSlot
   badge (:714/:777) all read the same value. In `loadWorkingHandsIfNeeded()`
   after `workingHands = ...`, set `casinoWithdrawn = myWorkingHand`.
   This keeps the sheet `withdrawn:` values correct without touching call sites.
4. **Remove `loadMyOpenWithdrawalIfNeeded`** from `refresh()` (the
   `withdrawalLoad` async let + its await). The settle sheets only need the
   points amount, never the `CasinoWithdrawal` row id, so the RPC is no longer
   needed. Keep `loadMyOpenWithdrawalIfNeeded` deleted entirely; leave
   `CasinoService.loadMyOpenWithdrawal` and migration 040 in place (harmless,
   documented as no-longer-authoritative).
5. **MascotEngine is unaffected** — it already takes `withdrawnAmount` as a
   param; RoomDetailView passes `myWorkingHand` (via casinoWithdrawn) the same
   way it does today. No change needed in MascotEngine.
6. **Live-DB verification** of `get_my_open_withdrawal` is a separate concern
   documented below; the client MUST NOT depend on it.
