# V0.66 — CAH settle CTA: visible option to settle CAH cards from any active event

## Goal

USER (2026-08-14): "how is someone meant to settle their CAH card tsar given
cards? there's no option in the UI to do this, it should be another CTA."

The CAH scan CTA ("Count your CAH cards") only renders when the ACTIVE EVENT'S
pack is `cards_against_humanity`. On a casino event there is NO way to reach
`CAHCardScanSheet` — the CAH settle surface is unreachable unless the event
itself is CAH. A night can mix packs (casino chips AND CAH cards at the same
table). The settle surface must offer BOTH: settle the casino working hand AND
settle CAH cards — as separate CTAs.

## Design decisions (owner: orchestrator — do not relitigate)

1. **Primary CTA stays the event pack's settle.** Casino → "Settle casino
   chips"; CAH → "Count your CAH cards". Unchanged.
2. **Secondary "Count your CAH cards" CTA renders for EVERY active event** when
   the room has the CAH pack installed. One tap behind the primary, styled as an
   outline button (matching the existing "Settle manually" secondary-link
   pattern) — never a second filled primary. One-CTA-per-state: primary filled,
   secondary outline.
3. **Wire to `cahScanEvent`** — the existing `CAHCardScanSheet` + `record_cah_tally`
   path is correct and member-writable.
4. **Hosts get the same secondary CAH CTA** (hosts can also hold CAH cards —
   lock 2026-07-09 host-can-play). `HostScoreEntrySheet` manual CAH entry stays
   as-is.
5. **Do NOT show the CAH CTA when the room lacks the CAH pack.** Gate on
   `roomService.cachedRoomPacks(roomId:)`; empty cache → all packs installed
   (matches the Operations sub-sheet convention).
6. **Do NOT render casino settle on CAH events.** `SettleCasinoSheet` requires a
   casino working hand (`withdrawn`), which does not exist on a CAH event — the
   CTA would open a sheet with `withdrawn: 0`, a meaningless no-op. CAH settle is
   pack-independent (count cards) so it makes sense everywhere; casino settle is
   tied to a casino working hand so it only makes sense on casino events.

## Deliverables

1. `roomHasCAHPack` computed property on `RoomDetailView` (empty cache → true).
2. `onCAHSettle` stored property on `WitnessSlot` (default nil), rendered as an
   outline button after the primary CTA, before the host-only `onScore` block.
3. `onCAHSettle: roomHasCAHPack ? { cahScanEvent = event } : nil` wired at all
   three WitnessSlot call sites (`.inPlay`, `.tonightEvent`, `.settleRound`).
4. No casino-settle secondary on CAH events (decision 6).
