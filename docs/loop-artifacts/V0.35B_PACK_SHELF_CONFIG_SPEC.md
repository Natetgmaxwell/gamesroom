# V0.35B — Pack shelf per-pack config (kanban t_6172dd03)

## Context

User feedback: "The settings icon under the Packs card doesn't do anything when I
tap on Casino or Cards Against Humanity. For Casino I expected to get vision
settings / chip values (like room settings). For CAH it should be points per
card given by the card czar."

Root cause: `PackShelfReadOnly`'s `onTapGesture` (RoomDetailView.swift:1969)
has two guards — `isHost` and `pack.scoringType == .singleWinner`. Casino
(`.withdrawReturn`) and CAH (`.countBased`) are both blocked by the second
guard, so the settings icon renders but does nothing.

Fix: route each scoring type to its own config surface. Single-winner keeps
the existing payout sheet; Casino opens the existing `RoomSettingsCasinoSheet`
(chip color map); CAH opens a new points-per-card sheet.

## Pinned decisions (do not re-decide)

1. **CAH config semantics**: the saved value is the room's default
   points-per-card, stored in the existing `RoomPackConfig.winPoints` override
   via `RoomService.setRoomPackConfig` (migration 047 path — no new migration).
   In the count-based model 1 card = 1 point, so "points per card" == the
   default cards-won per round. The value SEEDS the host's per-round
   "Cards won" stepper in `HostScoreEntrySheet` (currently hardcoded 1).
   Multiplier semantics (points × cards) are explicitly OUT OF SCOPE — they
   would require a migration + `record_cah_tally` change.
2. **Casino surface**: present the existing `RoomSettingsCasinoSheet(roomId:)`
   as a sheet, with `casinoService` in the environment. Same surface as Room
   Settings → Operations → Casino chips. Two ways to get there is fine.
3. **Routing**: switch on `pack.scoringType` in the tap handler. Keep the
   `isHost` guard. Members see no tap action (unchanged).
4. **No new Foundation tests**: this is surface-only view work; the Foundation
   slice (Models/ + Packs/) has no new logic. Existing tests must stay green.
5. **No commit by the implementer**: leave the working tree for the
   orchestrator, who stages hunks to exclude the drift hunk.

## Changes

### 1. PackShelfReadOnly — per-type routing (RoomDetailView.swift)

- Add `@EnvironmentObject private var casinoService: CasinoService`.
- Add `@State private var cahConfigPack: (any PackDefinition.Type)?` and
  `@State private var showingCasinoConfig = false`.
- Call site (~line 356): `PackShelfReadOnly(room: room)` gains
  `.environmentObject(casinoService)`.
- Tap handler: keep `guard isHost else { return }`, then switch on
  `pack.scoringType`:
  - `.singleWinner` → `payoutPack = pack` (unchanged)
  - `.withdrawReturn` → `showingCasinoConfig = true`
  - `.countBased` → `cahConfigPack = pack`
- Row caption: show for `.countBased` too. Extend the caption helper so
  count-based rows read "N pts per card" (same `effectiveWinPoints` lookup;
  "1 pt per card" singular form).
- Accessibility hint per type: singleWinner "Tap to change how much a win
  pays out"; countBased "Tap to change points per card"; withdrawReturn
  "Tap to change chip values"; members "".

### 2. Casino sheet presentation (RoomDetailView.swift)

- New `.sheet(isPresented: $showingCasinoConfig)` presenting
  `RoomSettingsCasinoSheet(roomId: room.id).environmentObject(casinoService)`.
  Reuse the sheet verbatim — no edits to RoomSettingsSheet.swift.

### 3. CAHConfigSheet (RoomDetailView.swift, next to PackPayoutSheet)

- New `private struct CAHConfigSheet`, mirroring PackPayoutSheet's shape
  (NavigationStack + Form + Cancel/Save toolbar), for count-based packs:
  - Stepper "N pts per card", range 1...20, step 1 (matches
    HostScoreEntrySheet's per-round cards-won range).
  - Footer: the value is the default points a won black card is worth in
    this room; the host can still adjust per round when scoring; the pack
    default is `PackRegistry.shared.winPoints(for: pack.slug)`.
  - Save → `roomService.setRoomPackConfig(roomId:packSlug:winPoints:)` then
    dismiss. Cancel → dismiss.
- Presented via a second `.sheet(item: Binding<AnyPackType?>(...))` on
  `cahConfigPack`, mirroring the existing payoutPack pattern.

### 4. HostScoreEntrySheet — seed cards-won from room config

- Add `let defaultCardCount: Int` and a custom init seeding
  `_cardCount = State(initialValue: max(1, defaultCardCount))`.
- Call site (RoomDetailView ~line 290): pass
  `defaultCardCount: roomService.effectiveWinPoints(roomId: room.id,
  packSlug: event.packSlug)`.
- No override → 1 (behavior unchanged). Override set → the stepper opens at
  the room's points-per-card.
