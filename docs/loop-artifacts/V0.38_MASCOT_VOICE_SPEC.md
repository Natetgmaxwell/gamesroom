# V0.38 — Mascot voice quality pass (kanban t_6c197ffc)

## Context

User feedback: "The mascot voice needs improvements."

Current state: `MascotEngine.swift` is a 5 personalities × 5 ideologies × 8
kinds = **200-cell** template matrix (the task body's "5×5×4 = 100" is the
pre-V0.36 count; V0.36 added 4 footer kinds). V0.36 made the room-page footer
room-state-aware, but the templates are still static strings with
`{placeholder}` substitution — they read as Mad Libs:

- "seat(s) open", "member(s)" — the `(s)` plural is the form-letter tell
- every personality says "took it home" for the winner (25 identical lines)
- personalities differ by word-swap, not voice (professional and friendly
  both defer to the host in the same words)
- unhinged is ALL-CAPS shouting, which violates the tone calibration
- the footer's `.briefingOnCreate` state renders "Poker is on the books at ."
  because `{time}`/`{venue}`/`{seats_left}` substitute `""` and the footer
  passes no date/venue/seats

gbrain (`concepts/2026-07-27-games-room-profile-aware-social-design`): "The
voice of the system should be something the masked-autistic host doesn't have
to perform — informational, light, not dramatic." VISION §5.3: "Mascot voice
is the footer caption (italic 13pt one-liner). Never the lead."

`generateVoice` has exactly ONE consumer: `MascotFooterCaption` in
RoomDetailView. `NotificationDispatcher` uses its own body builders for
pushes and calls `generateVoiceLLM` only when a room has a mascot API key.
So template changes and the placeholder-contract extension below are
contained to the engine + its tests.

## Design

### 1. Voice direction (pinned — do not re-decide)

| Personality | Signature moves | Banned |
|---|---|---|
| professional | Declarative only. Zero `!`. Terse, no opinion, no second-person digs. Host is "the host". | No `!`, no air quotes, no "we", no digs |
| friendly | Warm, inclusive ("we/our"), names people, encourages. **One** `!` max. | No digs, no irony, no second-person blame |
| snarky | Pointed but kind. One dig per body, then a fair line. Second-person group address ("the rest of you"). | No air quotes (that is sarcastic's move), no more than one dig |
| sarcastic | Dry irony. Air quotes on the host's claims, "Sure.", "I'm sure that'll hold." One irony per body. | Never two ironies (reads mean), no ALL-CAPS |
| unhinged | Normal case — **no ALL-CAPS**. Stream-of-consciousness: one non-sequitur per body (lamp, 3 AM, chair grid), fourth-wall aware, rapid subject shifts, **one** `!` max. | No ALL-CAPS, no shouting, ≤1 `!` |

Ideology axis keeps its existing character (order trusts the host, centrist
reads the room, trickster shuffles the standings, anarchist refuses
authority, apocalypse is light doom) — but delivery is unified: informational,
light, never dramatic. Apocalypse gets existential irony ("the end remains on
schedule"), not doom-shouting.

### 2. Per-kind fact recipes (every cell must satisfy)

| Kind | Facts that MUST appear (nil-safe via sentence-drop) | Extra facts allowed |
|---|---|---|
| briefingOnCreate | `{event}` in **sentence 1** (with `{mascot}:`); logistics `{time}` `{venue}` `{seats_left}` in **sentence 2** | claim prompt |
| briefing48h | `{event}` in sentence 1; logistics `{time}` `{venue}` `{seats_claimed}` in sentence 2 | cadence ("two days") |
| briefingMorning | `{event}` in sentence 1; logistics `{time}` `{venue}` `{seats_left}` in sentence 2 | today-nudge |
| postPlayRecap | `{event}` concluded + `{winner}` in a separate sentence | `{member_count}` |
| roomWelcome | `{room}` | "first night coming" |
| inPlay | `{event}` + `{leader}` | `{event_count}` |
| roomStale | `{room}` + `{days_quiet}` | comeback nudge |
| standings | `{room}` + `{leader}` | `{caller_rank}`, `{winner}`, `{event_count}` |

**Logistics-sentence rule (why sentence 2):** the only `generateVoice`
consumer is the footer, which never passes time/venue/seats. Putting the
legacy logistics placeholders in a standalone sentence 2 means the
sentence-drop pass removes exactly that sentence when the footer renders an
upcoming event — sentence 1 (`{mascot}: {event} …`) survives, so the mascot's
attribution is never lost. The logistics sentence renders only when a caller
actually supplies the values (tests, future push-path reuse).

### 3. Tone + grammar rules (testable)

1. No `(s)` Mad-Libs pattern anywhere ("seat(s)", "member(s)"). Rephrase with
   count-agnostic phrasing: "{seats_left} left", "{seats_claimed} in",
   "{member_count} strong".
2. ≤ 1 `!` per body across ALL personalities; unhinged additionally bans
   ALL-CAPS (no run of 3+ consecutive uppercase letters in the rendered
   output). "3 AM" is fine (2 caps).
3. ≤ 200 chars per fully-populated body (parity with the LLM path's
   `max_tokens: 120` cap).
4. Winner line is personality-native, never the uniform "took it home":
   professional "{winner} won the night.", friendly "Nice one, {winner}!",
   snarky "{winner} won — try to look surprised.", sarcastic "{winner} won.",
   unhinged "{winner} won."
5. 1–3 short sentences per body; unhinged chains clauses with commas/em-dashes
   instead of adding sentences.
6. Every cell keeps the `{mascot}: ` prefix in sentence 1 — it is the
   mascot's attribution in push bodies and the footer.

### 4. Placeholder-contract extension (deviation from V0.36, named)

V0.36 kept `{time}`, `{venue}`, `{seats_left}`, `{seats_claimed}` on `""`
substitution. V0.38 moves them into the nil-preserving + sentence-drop set
(alongside `{event}`, `{winner}`, `{leader}`, `{caller_rank}`, `{event_count}`,
`{days_quiet}`).

Why this is safe: the only `generateVoice` consumer is the footer, which
never passes date/venue/seats — today `.briefingOnCreate` in the footer
renders "Poker is on the books at .". After the change, the logistics
sentence drops cleanly. Push paths do not call `generateVoice` (they use
`NotificationDispatcher`'s own builders + `generateVoiceLLM`, which always
pass real values). The V0.36 "must not regress" clause referred to those
briefing paths; this extension cannot regress them.

`{date}` and `{host_note}` keep `""` substitution — no template references
them (0 uses), so the behavior is a no-op either way.

### 5. LLM systemPrompt tone line

Append to the existing `systemPrompt`: "Tone is informational and light —
a quiet footer caption, never dramatic. No ALL-CAPS. At most one
exclamation mark." Change "1-2 sentences" to "1-3 short sentences" for
parity with rule 3.5.
