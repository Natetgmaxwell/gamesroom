# V0.50 — Unify settle/score surface: vision-first for casino AND CAH, host or member

## Problem (user report)
"when you go to score a round or settle, this is where the vision chip counting
for the casino pack and the vision card counting for the cards against humanity
scoring [should be]. I can't see any of this in the app."

The vision scan surfaces (`ChipScanSheet`, `CAHCardScanSheet`) exist and work for
casino *members*, but hosts never reach them: the casino host's settle/score path
routes straight to the manual `SettleCasinoSheet`, and the CAH host's "Score a
round" routes to `HostScoreEntrySheet` (or, on iPad, to a dashboard that never
renders for count_based packs — nothing happens).

## Target behavior (per role × pack × state)

Vision scan is the PRIMARY settle/score CTA for BOTH packs and BOTH roles. The
manual / aggregate entry sits exactly ONE tap behind as a secondary link. One
filled primary button per slot; manual is a secondary link.

### Casino member (.inPlay / .settleRound)
- Primary scan CTA "Scan your chips" → `ChipScanSheet` (vision). *(already correct)*
- Secondary "Settle manually" → `SettleCasinoSheet(isHost:false)`. *(already correct)*

### Casino host (.inPlay / .settleRound)
- Primary scan CTA "Scan your chips" → `ChipScanSheet` (vision). The host may
  also have chips out (lock 2026-07-09), and `record_member_scan` is keyed off
  the caller's own withdrawal row, so a host who withdrew can scan their own
  chips cleanly.
- Secondary "Score a round" → `ChipScanSheet` (vision). Same sheet as the
  primary scan — the host gets the vision count surface.
- Tertiary aggregate/manual link → `SettleCasinoSheet(isHost:true)`. One tap
  behind the vision flow.

### CAH member (.inPlay / .settleRound)
- Primary scan CTA "Scan your cards" → `CAHCardScanSheet` (vision). *(already correct)*
- No manual link (count-based has no manual settle path). *(already correct)*

### CAH host (.inPlay / .settleRound)
- Primary scan CTA "Scan your cards" → `CAHCardScanSheet` (vision). *(already correct via openScan)*
- Secondary "Score a round" → `CAHCardScanSheet` (vision). `record_cah_tally` is
  caller-scoped and requires only room membership — a host who plays can scan
  their own card tally cleanly.
- Tertiary manual entry link → `HostScoreEntrySheet`. One tap behind the vision
  flow.

## Working hand badge (item 2)
Keep casino-only (CAH has no chip-withdrawal concept). `WitnessSlot` already
renders `workingHand` from `casinoWithdrawn`, which is the caller's own open
withdrawal (`get_my_open_withdrawal`, fixed in t_350c0cd7 / commit 1c8ce98). It is
passed in both `.inPlay` and `.settleRound` for all roles, so a host who withdrew
sees it exactly like a member. **No change needed** beyond confirming the value
populates (verification).

## Routing changes (RoomDetailView.swift only)

### 1. `settleSheetEvent` sheet binding (currently ~line 288-313)
Drop the `if isHost { SettleCasinoSheet } else { ChipScanSheet }` branch. This
binding is the VISION surface — always present `ChipScanSheet` regardless of role.

### 2. `openHostScore(event:)` (currently ~line 988-997)
Restructure on `scoringType`:
- `.withdrawReturn` (casino): `settleSheetEvent = event` → ChipScanSheet (vision).
- `.countBased` (CAH): `cahScanEvent = event` → CAHCardScanSheet (vision).
- default (`single_winner`): unchanged — iPad regular → dashboard, else
  `hostScoreEvent`. *(Fixes the CAH-on-iPad dead tap: dashboard gate only renders
  `single_winner`, so count_based must NOT route there.)*

### 3. Host aggregate/manual links
- Add `@State private var hostManualSettleSheetEvent: Event?`.
- Add `.sheet(item: $hostManualSettleSheetEvent)` → `SettleCasinoSheet(isHost:true)`
  (casino host aggregate settle).
- CAH host manual entry reuses the existing `hostScoreEvent` binding →
  `HostScoreEntrySheet`.
- Add `hostManualSettleAction(for:)` helper: casino host → flips
  `hostManualSettleSheetEvent`; CAH host → flips `hostScoreEvent`; nil otherwise.

### 4. `WitnessSlot` call sites (.inPlay ~598, .settleRound ~656)
Pass a new `onHostManualSettle` callback (host only) alongside the existing
`onManualSettle` (member only). `WitnessSlot` renders the host manual link as a
secondary link below the "Score a round" button — never a second filled
full-width primary.
