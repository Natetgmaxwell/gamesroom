## Night-flow trace (withdraw → dispense → play → settle → narrate)

1. **Withdraw (member).** `.tonightEvent` (live, `casinoWithdrawn == 0`) renders the
   WitnessSlot with the full-width "Withdraw chips" CTA → `openWithdraw` →
   `WithdrawChipsSheet` → `CasinoService.withdraw` → `withdraw_casino_chips` (061).
   On success `refresh(force: true)` re-reads the open withdrawal →
   `casinoWithdrawn > 0` → state flips to `.inPlay`.
2. **Host sees + dispenses.** `loadHostWithdrawalsIfNeeded` (host-only, casino pack)
   reads `get_event_transactions` (024), filters `kind == "casino_withdrawal"`, and
   renders the "Chips to dispense" section. "Dispensed" is local state only — the
   ledger is never mutated by this surface (by design, V0.47).
3. **Working hand visible.** `.inPlay` / `.settleRound` pass
   `workingHand: casinoWithdrawn` → the "Working hand: N pts" badge in the witness
   hero.
4. **Settle.** Casino member gets BOTH paths: vision chip-scan (`openScan` →
   `ChipScanSheet` → `record_member_scan` 030) and "Settle manually" (`openScan`'s
   secondary link → `SettleCasinoSheet`). CAH member gets `CAHCardScanSheet` →
   `record_cah_tally` (055). Host settles via `SettleCasinoSheet` →
   `record_round_score` (035).
5. **Ledger posts.** Member vision/manual → `record_member_scan` writes a
   `casino_settlement` transaction with net = returned − withdrawn. Host → 
   `record_round_score` writes `round_submissions` + per-member deltas.
6. **Mascot narrates.** `MascotFooterCaption` resolves `footerKind` from
   `(activeEvent, leaderboard, withdrawnAmount, currentSeason)` mirroring the
   `V0State` precedence: seasonClose → postPlayRecap → settleRound →
   tonightEvent → inPlayWithWithdrawal → briefingOnCreate → roomWelcome →
   roomStale → standings. `{working_hand}` / `{last_delta}` / `{season_days_left}`
   join the nil-preserving sentence-drop set.

## Integration fix (this pass)

**Member "Settle manually" posted to a host-only RPC.** `SettleCasinoSheet.save()`
unconditionally called `ScoringService.recordRoundInput` → `record_round_score`
(migration 035), which raises "Only the host can record a round" for a non-host
member. The V0.46 spec scoped out backend changes, so the member manual path was
silently broken.

Fix: `SettleCasinoSheet` gained an `isHost` flag (default `true`). Host keeps the
aggregate `recordRoundInput` path; member routes through
`CasinoService.submitMemberScan(source: .manual)` → `record_member_scan` (030),
which is member-writable and computes net = returned − withdrawn. The member manual
call site passes `isHost: false` and injects `casinoService`.

## RPC contract drift

No new RPCs were added by the batch — all four commits are client-side only (no
Supabase migration touched). The flow reuses audited RPCs:
`withdraw_casino_chips` (061), `get_event_transactions` (024),
`get_my_open_withdrawal` (040), `record_member_scan` (030), `record_round_score`
(035), `record_cah_tally` (055). All client decode shapes match their RPC
`RETURNS TABLE` columns (verified: `EventTransaction` ↔ 024, `CasinoWithdrawal` ↔
061/040, `ScoreSubmission` ↔ 035).

Pre-existing note: migration 040's local file references `casino_withdrawals.event_id`
/ `.settled_at` (columns that don't exist — the table uses `session_id`). Migration
056 documents the remote patch to `session_id` + `casino_scans`. The client decodes
`session_id`, matching the actual table. Not introduced by this batch.
