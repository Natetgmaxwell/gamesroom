## Fix 1 — Delete confirmation (required by spec §4)

Current: `onDelete: { round in Task { await deleteRound(round) } }` fires the
delete immediately on trash tap. Deleting reverses every member's season score
— a mis-tap is destructive with no undo.

Required:
- Add `@State private var roundToDelete: EventRound?`.
- Timeline `onDelete` sets `roundToDelete = round` (no Task, no direct call).
- Add `.confirmationDialog` (or `.alert`) on the root VStack, presented when
  `roundToDelete != nil`: title "Delete round N?" (use the round's index),
  message "This reverses the score change for everyone in the round.",
  confirm button (destructive role) → `Task { await deleteRound(round) }` then
  clear `roundToDelete`; cancel → clear `roundToDelete`.
- `deleteRound` keeps its current body (deleteRound RPC, reload rounds, reseed
  nextRoundIndex, clear edit state if the deleted round was being corrected).

## Fix 2 — Leaderboard reload after mutation (required by spec §5)

Current: `save()` and `deleteRound()` reload rounds but never reload the
leaderboard, so the standings strip (`cachedLeaderboard`) goes stale after
logging a win or deleting a round.

Required: in `save()` after the successful `recordRoundInput` (before or
after the rounds reload) and in `deleteRound()` after the successful
`deleteRound` call, add:
`_ = await roomService.loadLeaderboard(roomId: room.id)`
(RoomService.loadLeaderboard exists at line ~357; it returns
`[LeaderboardEntry]` and updates the cache the standings strip reads.)
