## Task

Cards Against Humanity currently scores as single_winner, 1 point per
round. In real CAH the winner keeps the black card; the score is the
COUNT of black cards held, not rounds won. Change CAH to count-based
scoring (host enters cards won per round, default 1) and add a
member-facing vision card-counting flow that reuses the landed Casino
vision infrastructure (camera + segmentation detector + confirm).

## Design decisions (pinned — follow exactly)

1. **New scoring type.** Add `case countBased = "count_based"` to
   `PackScoringType` in PackDefinition.swift. Update the enum doc
   comment to describe the three families. Add a computed property
   `var displayLabel: String` on PackScoringType: singleWinner →
   "Single winner", withdrawReturn → "Withdraw & return", countBased →
   "Count-based". Use it at the three label sites (PackDetailView
   header, RoomSettingsSheet pack row, and anywhere else that
   duplicates the ternary).

2. **CAH pack.** In Packs.swift: `CardsAgainstHumanityPack.scoringType
   = .countBased`. Update its doc comment. Change its `description`
   to EXACTLY: "Card-judging party game. The judge's pick wins the
   round and keeps the black card — score is cards won."
   Keep `winPoints = 1` (it is the default card count; PackRegistry
   still returns it).

3. **New input case.** In PackScoring.swift add
   `case countBased(roundIndex: Int, winnerMemberId: UUID, cardCount: Int)`
   to PackScoringInput. `packSlug` returns "cards_against_humanity".
   Resolver branch: one ScoreEntry, `pointsDelta = Int64(cardCount)`,
   meta `["winner": .bool(true), "cards_won": .int(Int64(cardCount)),
   "round_index": .int(Int64(roundIndex))]`.

4. **Host entry UI.** HostScoreEntrySheet: when the event's pack
   scoringType is `.countBased`:
   - Winner selection is single-select (tapping a member selects only
     them; tapping the selected member deselects). No multi-winner for
     count-based.
   - Show a "Cards won" Stepper (default 1, range 1...20) in place of
     the round-index-only footer; keep the round-index stepper.
   - Footer text: "The judge's pick wins the round and keeps the black
     card. Enter how many cards the winner takes (usually 1)."
   - Submit `.countBased(roundIndex:winnerMemberId:cardCount:)`.
   - For `.singleWinner` packs the sheet is unchanged (chip tray
     multi-select + effectiveWinPoints).
   Look up the pack via `PackRegistry.shared.definition(for:
   packSlug)` to read scoringType.

5. **Payout editor gate.** In RoomDetailView packRow: the tap-to-edit
   payout (`payoutPack = pack`) must only fire for `.singleWinner`
   packs. Count-based packs are not tappable for payout (a room-level
   win-points override is meaningless when the count IS the score).
   The payout caption is already gated to `.singleWinner` — leave it.

6. **Leaderboard display fix.** StandingsSection (RoomDetailView
   ~line 1578) passes `Int(entry.pointsBalance)` to LeaderboardRow.
   Change to `Int(entry.seasonScore)`. Rationale: the leaderboard
   RPC ranks by season_score; displaying points_balance (the casino
   wallet, seeded at 200, never touched by round_score) disagrees
   with the ranking and shows 0 for CAH rooms. seasonScore is the
   season standings number and for CAH it IS total cards won. This is
   required by the acceptance criterion "Season leaderboard shows
   total cards won".

7. **Detector parameterization.** ChipSegmentationDetector: add
   `let pxPerUnit: Double` with init default `10` (chips). Count
   becomes `max(1, Int((boxH * Double(height) / pxPerUnit).rounded()))`.
   Casino call sites unchanged (default). The CAH scan uses
   `ChipSegmentationDetector(pxPerUnit: 2)` — cards are thinner than
   chips; the estimate is rough by design and the member confirms/
   adjusts (vision is assistant, not authority — same trust model as
   casino).

8. **CAH scan sheet.** NEW file GamesRoom/Views/CAHCardScanSheet.swift.
   Model it on ChipScanSheet but simpler:
   - Camera: reuse `ScanCameraPreview` (defined in ChipScanSheet.swift).
   - On frame: hash the JPEG (PhotoHash.sha256) and DISCARD the bytes
     (no opt-in photo retention for CAH — discard-only, per privacy
     posture). Run `ChipSegmentationDetector(pxPerUnit: 2).detect(cg:)`.
     Sum stack counts → total cards. No chip colors, no withdrawn, no
     net delta.
   - Confirm view: "Your cards: N" (display size), confidence line,
     editable total via Stepper (1...100), "Looks right — record N
     cards" button, "Re-scan" button. Low-confidence / empty detection
     → guidance text + re-scan (same pattern as ChipScanSheet).
   - Submit: `scoringService.recordCAHTally(eventId:cardCount:
     visionSnapshot:)` with a VisionSnapshot(stacks:totalValue:
     confidenceAvg:discarded:false, photoHash:). Then onDone + dismiss.
   - Add the file to GamesRoom.xcodeproj/project.pbxproj (PBXFileReference
     + PBXBuildFile + Sources phase, following the existing ID pattern
     AAAAAAAA00000000000004XX). Run scripts/verify-xcode-project.py.
