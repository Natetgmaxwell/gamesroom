# V0.47 — Banking-style withdrawal: host chip-dispensing surface + balance re-read

## Goal
Withdrawals must behave like a banking system: funds must be available to withdraw, and when a member withdraws the HOST must see it so they can dispense the physical chips. This slice adds the host-side "Chips to dispense" surface and hardens the member balance re-read.

## Current state (verified in tree)
- Server already guards availability: migration 025 `withdraw_casino_chips` derives room from event, reads `room_memberships.points_balance`, raises errcode 23514 when balance < p_points. Do NOT change the ledger.
- Client `WithdrawChipsSheet` (GamesRoom/Views/WithdrawChipsSheet.swift): stepper range is `10...max(10, balance)`; the Withdraw toolbar button is `.disabled(isSaving || isLoadingBalance || amount > balance)` (line 106). Balance loads once via `.task { await loadBalance() }`. On submit failure `save()` catches and sets `errorMessage`, which renders as a red-text Form Section — visible, non-crashing, not a silent no-op. **This already satisfies "no crash / no silent no-op"; keep the errorMessage surface.**
- Balance re-read: `.task` fires once per sheet presentation. There is no `.refreshable` — if the balance changes while the sheet is open (double-device race), the slider bound stays stale until the server rejects. Add pull-to-refresh so the member can re-read.
- Host visibility: NO surface exists. `CasinoService.getEventTransactions(eventId:)` (CasinoService.swift:443) wraps migration 024 RPC and returns `[EventTransaction]` with `member_id`, `member_display_name`, `kind`, `amount_points`, `meta`, `created_at`. `kind == "casino_withdrawal"` rows carry `amount_points` = `-p_points` (negative). No view renders it.
- `HostScoringDashboard` (HostScoringDashboard.swift) is gated in RoomDetailView `showScoringDashboard` to `pack.scoringType == .singleWinner`. **The Casino pack is `withdrawReturn` (Packs/Packs.swift:33), so HostScoringDashboard NEVER renders for casino.** The host withdrawals board must live in RoomDetailView's `scrollBody` as a host-only section.
- `RoomDetailView` (RoomDetailView.swift): `isHost` computed (line 117); `scrollBody` (line 364) stacks `activeSlot`, `SystemBanner`, `StandingsSection`, `RoundBreakdownSection`, `SeasonHistorySection`, two `CollapsibleSection`s, then `MascotFooterCaption`. `refresh()` (line 673) runs many async loads in parallel via `async let`. `CasinoService` is an `@EnvironmentObject`.

## Changes

### 1. RoomDetailView.swift — host-only "Chips to dispense" section
Add two `@State` vars near the other casino state (near line 73):
```swift
/// Host-only: pending `casino_withdrawal` transactions for the active
/// event. Loaded in `refresh`; the host dispenses physical chips and
/// taps Dispensed to acknowledge (local state, ledger unchanged).
@State private var hostWithdrawals: [EventTransaction] = []
/// Transaction ids the host has already dispensed this session. Local
/// only — the ledger is never mutated by this acknowledgement.
@State private var dispensedWithdrawalIds: Set<UUID> = []
```

Add a loader (mirrors `loadMyOpenWithdrawalIfNeeded` and `loadActiveIfNeeded` patterns):
```swift
/// Loads the host-only pending-withdrawal list. Guards on host role and
/// the active event being casino; ensures the active event is cached
/// first so ordering within the parallel `refresh` doesn't matter.
private func loadHostWithdrawalsIfNeeded() async {
    guard isHost else {
        hostWithdrawals = []
        return
    }
    if roomService.cachedActiveEvent(roomId: room.id) == nil {
        await roomService.loadActiveEvent(roomId: room.id, force: false)
    }
    guard let event = activeEvent, event.packSlug == "casino" else {
        hostWithdrawals = []
        return
    }
    let all = await casinoService.getEventTransactions(eventId: event.id)
    hostWithdrawals = all.filter { $0.kind == "casino_withdrawal" }
}
```

Wire it into `refresh()`'s parallel block (add one `async let` + await it):
```swift
async let withdrawalsLoad: () = loadHostWithdrawalsIfNeeded()
```
and add `withdrawalsLoad` to the existing `_ = await (active, board, ..., withdrawalsLoad, ...)` tuple.

Add a computed pending list:
```swift
/// Withdrawals still awaiting physical chip dispensing.
private var pendingWithdrawals: [EventTransaction] {
    hostWithdrawals.filter { !dispensedWithdrawalIds.contains($0.id) }
}
```

Render the section in `scrollBody`, placed right after `activeSlot` (before `SystemBanner`) so the host sees it immediately. Show only when host + casino + there are pending withdrawals; hide entirely when empty (matches the conditional-section pattern of StandingsSection):
```swift
if isHost,
   let event = activeEvent,
   event.packSlug == "casino",
   !pendingWithdrawals.isEmpty {
    HostWithdrawalsSection(
        withdrawals: pendingWithdrawals,
        onDispense: { id in dispensedWithdrawalIds.insert(id) }
    )
    .sectionCard(.standard)
}
```

### 2. RoomDetailView.swift — new private `HostWithdrawalsSection`
Add a private struct (in this file, near the other private section structs). Each row: member display name + amount (absolute value, since `casino_withdrawal` is negative) + a "Dispensed" button that calls `onDispense(txn.id)`:
```swift
/// Host-only list of pending chip withdrawals to physically dispense.
/// Member name + amount, with a tap-to-dismiss "Dispensed"
/// acknowledgement. Local state only — the ledger is never mutated.
private struct HostWithdrawalsSection: View {
    let withdrawals: [EventTransaction]
    let onDispense: (UUID) -> Void

    var body: some View {
        VStack(alignment: .leading, spacing: Theme.Layout.cardInset) {
            HStack(spacing: 8) {
                Image(systemName: Theme.Icon.circleHexagongridFill)
                    .foregroundStyle(Theme.Palette.accent)
                Text("Chips to dispense")
                    .font(Theme.Typography.title)
                    .foregroundStyle(Theme.Palette.primaryText)
            }
            ForEach(withdrawals) { txn in
                HStack(spacing: Theme.Layout.cardInset) {
                    VStack(alignment: .leading, spacing: 2) {
                        Text(txn.memberDisplayName)
                            .font(Theme.Typography.body)
                            .foregroundStyle(Theme.Palette.primaryText)
                        Text("Withdrew chips")
                            .font(Theme.Typography.caption)
                            .foregroundStyle(Theme.Palette.primaryText.opacity(0.55))
                    }
                    Spacer()
                    Text("\(abs(txn.amountPoints)) pts")
                        .font(Theme.Typography.body.weight(.semibold).monospacedDigit())
                        .foregroundStyle(Theme.Palette.accent)
                    Button {
                        onDispense(txn.id)
                    } label: {
                        Text("Dispensed")
                            .font(Theme.Typography.caption.weight(.semibold))
                            .foregroundStyle(Theme.Palette.background)
                            .padding(.horizontal, 12)
                            .padding(.vertical, 8)
                            .background(
                                RoundedRectangle(cornerRadius: 8)
                                    .fill(Theme.Palette.accent)
                            )
                    }
                    .buttonStyle(.plain)
                    .accessibilityLabel(Text("Dispensed \\(txn.memberDisplayName)'s \\(abs(txn.amountPoints)) points"))
                }
            }
        }
        .frame(maxWidth: .infinity, alignment: .leading)
    }
}
```

## Acceptance criteria
- Host opens the active casino event → sees a "Chips to dispense" section listing every withdrawal with member name + amount (absolute value).
- Tapping "Dispensed" clears that withdrawal from the pending list (local state; the ledger is unchanged).
- When all pending withdrawals are dispensed (or there are none), the section is hidden.
- Member double-withdraw race: server raises 23514 → WithdrawChipsSheet shows the errorMessage (red text, visible), no crash, no silent no-op. Button stays disabled when amount > balance.
- Member can pull-to-refresh the sheet to re-read their balance.
- Tests + parse-checks + verify-xcode-project green (`./build-and-run-tests.sh`, `./scripts/parse-check-swiftui.sh`, `./scripts/verify-xcode-project.py`).

## Out of scope
- Backend / RPC / migration changes. The ledger is never mutated by the Dispensed acknowledgement.
- Physical-chip Vision pipeline.
- The member-visible working hand (already shipped in V0.46).
