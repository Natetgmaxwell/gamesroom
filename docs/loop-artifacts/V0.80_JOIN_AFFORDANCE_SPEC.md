## V0.80 — Join-Room Affordance for Existing Members

### Problem
Join exists ONLY in the empty state (`RoomPage.swift:458`, "Ask a friend for a join code"). Once a user belongs to any room, there is NO join path — the toolbar carries only + (create) and host-only settings (`RoomPage.swift:511-532`). Connor joining Games Room via Test Room code is impossible from the app today. Backend + sheet + service already work (`redeem_join_code` RPC, `JoinRoomSheet`, `RoomService.redeemJoinCode`).

### Fix — 2 changes

**1. RoomPage toolbar (RoomPage.swift:506-533)**
Add a second trailing toolbar button — door icon — opening `JoinRoomSheet`. Semantics:
- Renders whenever `!roomService.rooms.isEmpty` (mirrors the + button's gate at :511), so join is reachable from every non-empty state.
- Icon: `Theme.Icon.personCropCircleBadgePlus` (SF Symbol availability: iOS 16+; deployment target 26.0 — safe).

WAIT — check Theme.Icon first. The repo convention is Theme.Icon tokens, not raw SF names. Use existing `Theme.Icon.plus` sibling pattern; if no door/enter icon exists in Theme.Icon, add ONE new token with a doc comment in Theme.swift following the V0.79 bell pattern (`Theme.swift:176-179`).

**2. Empty-state copy (RoomPage.swift:446-466)**
The empty-state join button label reads "Ask a friend for a join code" — that is the discovery surface, keep as-is. No copy changes needed in this slice.

### Non-goals
- No server work. `redeem_join_code` RPC handles membership insert + starting-bonus ledger entry.
- No changes to JoinRoomSheet itself.
- No new tests beyond existing suite.
- No notification scheduling changes (`scheduleCatchUpIfNeeded` already fires post-join).

- With ≥1 room: toolbar shows both + and the join (door) button; tapping join opens JoinRoomSheet; redeeming a valid code adds the room + fires join-starting-bonus.
- Empty state unchanged.
