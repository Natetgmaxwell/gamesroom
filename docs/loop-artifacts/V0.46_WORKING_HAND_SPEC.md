# V0.46 — Withdraw-then-settle flow: working hand + dual settle paths

## Goal
After a member withdraws casino chips, the app tells them their working hand
immediately, and the settle/score surface offers BOTH a vision chip-scan path
(ChimScanSheet) AND a manual settle path (SettleCasinoSheet) — the member picks,
not hard-routed. CAH keeps its card-count scan. Host flow unchanged.

## Current state (verified in tree)
- `RoomDetailView` V0State machine (RoomDetailView.swift):
  - `.tonightEvent` = live && `casinoWithdrawn == 0` → WitnessSlot
    `cta: isCAH ? .scan : .withdraw`.
  - `.inPlay` = live && `casinoWithdrawn > 0` → WitnessSlot `cta: .scan`,
    `scanTitle` switches on pack.
  - `.settleRound` = live && hostFinalized → WitnessSlot `cta: .scan`.
- `casinoWithdrawn: Int` (@State, line 73) is the member's withdrawn amount,
  loaded by `loadMyOpenWithdrawalIfNeeded()` in `refresh()`.
- `openScan(event:)` (line 883): CAH → `cahScanEvent` (CAHCardScanSheet);
  non-CAH → `settleSheetEvent`.
- `.sheet(item: $settleSheetEvent)` binding (line 269): `isHost` →
  SettleCasinoSheet; else → ChipScanSheet (vision). So a MEMBER tapping scan
  today gets vision chip-scan. There is NO member path to SettleCasinoSheet.
- Host settle path: `settleSheetEvent` → SettleCasinoSheet; host "Score a round"
  → `openHostScore` → `settleSheetEvent` → SettleCasinoSheet. Both unchanged.
- `WitnessSlot` (RoomDetailView.swift:1315, private struct): renders header
  (title+caption), attestation rows, then CTA switch (withdraw|scan), then
  host-only "Score a round".
- `casinoWithdrawn` is 0 for CAH events (CAH never withdraws) — safe to pass,
  but gate on pack to keep semantics clean.

## Changes

### 1. Theme.swift — new icon
Add to `Theme.Icon`:
```swift
/// The working-hand badge on the in-play witness slot.
static let handPointUpFill = "hand.point.up.fill"
```

### 2. RoomDetailView.swift — new member manual-settle sheet
Add `@State private var manualSettleSheetEvent: Event?` near line 73.
Add a `.sheet(item: $manualSettleSheetEvent)` binding that ALWAYS presents
SettleCasinoSheet (member or host — this is the member's manual path):
```swift
.sheet(item: $manualSettleSheetEvent) { event in
    SettleCasinoSheet(
        eventId: event.id,
        roomId: room.id,
        withdrawn: casinoWithdrawn
    )
    .environmentObject(scoringService)
    .environmentObject(authService)
}
```

### 3. WitnessSlot — working-hand badge + manual-settle link
Add two optional stored props:
```swift
/// Working hand (withdrawn chips) to surface in the hero badge.
/// nil = don't render (CAH / not-yet-withdrawn).
var workingHand: Int? = nil
/// Casino-member "Settle manually" callback. nil = don't render the
/// manual link (host uses Score-a-round; CAH has no manual path).
var onManualSettle: (() -> Void)? = nil
```
In `body`, after the header HStack and before the attestation ForEach, render a
working-hand badge when `workingHand > 0`:
```swift
if let workingHand, workingHand > 0 {
    HStack(spacing: 6) {
        Image(systemName: Theme.Icon.handPointUpFill)
        Text("Working hand: \(workingHand) pts")
    }
    .font(Theme.Typography.caption.weight(.semibold))
    .foregroundStyle(Theme.Palette.accent)
    .padding(.horizontal, 10)
    .padding(.vertical, 6)
    .background(Theme.Palette.accent.opacity(0.12))
    .clipShape(Capsule())
    .accessibilityLabel(Text("Working hand: \(workingHand) pts"))
    .padding(.top, 4)
}
```
In the `.scan` CTA case, below the scan button, render a secondary manual link
when `onManualSettle` is non-nil (one tap behind the primary scan CTA):
```swift
if let onManualSettle {
    Button(action: onManualSettle) {
        Text("Settle manually")
            .font(Theme.Typography.caption.weight(.semibold))
            .foregroundStyle(Theme.Palette.accent)
            .frame(maxWidth: .infinity)
            .padding(.vertical, 12)
            .overlay(RoundedRectangle(cornerRadius: 12).stroke(Theme.Palette.accent))
    }
    .buttonStyle(.plain)
    .pressScale()
    .padding(.top, 8)
    .accessibilityLabel(Text("Settle manually instead of scanning"))
}
```

### 4. RoomDetailView.swift — wire the witness call sites
Helper to compute the member settle path (avoids repeating the guard):
```swift
private func manualSettleAction(for event: Event) -> (() -> Void)? {
    // Host settles via SettleCasinoSheet through settleSheetEvent /
    // openHostScore — never through the manual link. CAH has no manual path.
    guard !isHost, event.packSlug != "cards_against_humanity" else { return nil }
    return { manualSettleSheetEvent = event }
}
```
- `.inPlay` call site: add
  `workingHand: isCAH ? nil : (casinoWithdrawn > 0 ? casinoWithdrawn : nil),`
  and `onManualSettle: manualSettleAction(for: event)`.
- `.settleRound` call site: add the same two params.
- `.tonightEvent` call site: workingHand is nil (no withdrawal yet) — no change
  needed, but pass `onManualSettle: nil` explicitly or leave default nil.

## Acceptance criteria
- Casino member withdraws → `.inPlay` witness hero shows a "Working hand: N pts"
  badge with the withdrawn amount (matches `casinoWithdrawn`).
- Casino member taps scan → ChipScanSheet (vision) opens; "Settle manually" link
  sits one tap behind it and opens SettleCasinoSheet.
- CAH member taps scan → CAHCardScanSheet opens; no manual link, no working-hand
  badge (CAH is count-based).
- Host: scan and "Score a round" both open SettleCasinoSheet (unchanged); no
  manual link (host already has the settle surface).
- Tests + parse-checks green (`./build-and-run-tests.sh`).

## Out of scope
- Backend / RPC changes.
- Physical-chip Vision pipeline (dormant).
- Any change to CAH card-count flow or host settle flow.
